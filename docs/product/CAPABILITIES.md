# 添加能力

打开个人空间菜单 → **添加能力**。主聊天界面只保留入口，管理页由可信宿主持有。
自定义界面使用 `client.host.openCapabilities()` 打开同一页面，不需要复制管理逻辑。

## 三种添加方式

1. **选一种做法**：内置“资料对照”“会议变行动”“文字打磨”三个原创 Skill。
   添加后启用，之后在普通对话中提出需求。Skill 提供做事方法，不会凭空增加联网或执行权限。
2. **导入包**：选择插件文件夹，或导入单个 `SKILL.md`、MCP JSON、包含 `files` 的 JSON 文本包。
   支持 `.codex-plugin/plugin.json`、`.claude-plugin/plugin.json`、标准 Skills 和受支持的通用 `plugin.json` 组件。
3. **连接服务**：输入 MCP Streamable HTTP 地址；HTTPS 或本机 loopback HTTP。也支持导入本地 stdio 服务配置。

导入后不会运行程序。查看来源与组件，再决定是否启用。若依赖原 Agent 的 hooks、agents、commands、LSP、apps 等，页面会说明缺项；不是“全部插件即装即用”。

## MCP 工具

展开能力详情，查看地址或将启动的命令与参数。确认信任来源后，点击“连接并查看工具”，
勾选允许 AI 使用的工具，保存选择，再启用。首版只授权服务声明为只读的工具。

本地服务按当前 Windows 用户权限运行。环境配置与模型账户不自动继承；**这不是操作系统沙箱**。
“只读”是服务的声明，并不能保证恶意服务无副作用。请只连接你信任的服务。
当前不支持自动安装 npm/uv 依赖、OAuth 登录、旧版 SSE-only 服务或需要启动脚本的 Skill。
`node`、`python` 使用产品配置的运行时，其他程序必须填写已经安装的绝对路径。

配置示例：

```json
{
  "mcpServers": {
    "notes": {
      "type": "http",
      "url": "https://your-service.example/mcp",
      "headers": {"Authorization": "Bearer ${MORROW_PLUGIN_NOTES_TOKEN}"}
    }
  }
}
```

该地址是格式示例，不是已经验证的公共服务。密钥保存在你自己设置的 `MORROW_PLUGIN_` 环境变量中；
不要写入包或分享文件。修改启动环境后重启本地服务。

启用后直接告诉 AI 需求。模型先发现能力，再按需读取 Skill、参考材料或工具参数定义。
真实工具返回会进入原有任务记录，AI 可以据此整理答案、继续调用其他已授权工具或保存文件。
任务中可以停止；在管理页停用能力也会中止本进程拥有的对应调用。网络中断或崩溃后若结果无法确认，会保留不确定记录，不自动重发。

## 搭配与版本

“我的搭配”中选择能力、命名并保存。“启用这组能力”只启用已导入的对应版本与原先授权的工具，
不安装缺失组件，不扩大授权，也不关闭其他能力。任何一项缺失、版本不一致或尚未就绪时，整组不会部分生效。

导出只包含搭配名称、能力名称、适配格式、ID 与版本摘要；不包含聊天、记忆、接口地址、程序参数、密钥或本机路径。
收件人导入后能看到已有和缺失项，需要自行取得源项目/能力包、配置服务并授权。分享清单不是可执行安装包。

重新导入不同内容会保存为待用版本，当前版本保持运行。切换版本后处于停用状态；重新检查并启用。
MCP 重新连接会清空该组件原有工具选择；每次实际调用还会检查服务当前定义是否与已授权定义一致。

## 开发验收入口

```powershell
node tools/product_core021_demo.mjs
node tools/product_core021_demo.mjs --deepseek
```

第一条使用脚本模型和真实本地 MCP 子进程；第二条明确使用既有加密 DeepSeek 凭据，串行请求、无自动重试。
两者使用全新 `.test-data` 根。原 CORE-019 邀请包未重建，不包含此功能；当前可在源码运行版体验。
