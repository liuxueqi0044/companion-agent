## 1. 唯一链路

独立工作者（用户）在桌面伙伴中完成一次真实工作后，把这次工作里学到的规则保存下来，下次换个输入直接复用。

```text
文本需求 + CSV              （用户提供）
  → 结构化结果 + 待确认问题  （桌面成果卡，可核对）
  → 用户纠正                （改字段、答问题、补规则）
  → 提议保存为可重复功能      （用户接受或拒绝）
  → 新输入再次使用           （新文本 + 新 CSV，无需重新教学）
```

用户故事（首版唯一故事）：

> 一名独立工作者收到客户的询价文字，并手头有一份自己的条目价格表 CSV，表格里写明币种。
> 他把这段文字和 CSV 交给桌面伙伴，得到一份整理好的需求与明细结果：每条字段都能看出是从哪来的，能由已知数量与单价算出的行小计与合计按十进制定点给出并记录公式，缺信息的地方被单独标成待确认问题。
> 他改掉一处读错的字段、回答了两个问题，并确认一条以后要沿用的做法：“币种一律取清单里写明的 currency 列，不要按客户所在地猜。”
> 伙伴指出这属于会重复出现的做法，提议把它保存成一个可重复使用的功能；他查看规则摘要后接受。
> 接受只是授权制作候选包：候选包经历 draft → testing → ready，独立验证通过、包哈希与拟发布版本一致、授权覆盖该版本与所需权限后，才切换 active 指针；缺少覆盖该版本的授权时先请他确认，验证未过则显示失败原因并允许修改或取消。
> 下一次他把另一段需求文字和另一份同结构 CSV 交进来，这是一个新的业务任务（新 task_id、业务幂等键、初始 attempt），运行时固定使用已发布的技能版本。结果结构与上次一致、已确认的规则自动生效、缺失信息照样被标成待确认，不需要他把规则重讲一遍。

单链声明：本链路只有这一条。没有“仅文本、无 CSV”的替代变体，没有后台自动运行的变体，没有面向团队或多人的变体。任一替代路径若被需要，属于后续任务卡，不在本卡内。

两条边界澄清（D1、D2）：S4 内部的验证与发布阶段是同一个用户可见步骤的内部阶段，不构成第二条用户链路；会话不等于任务，同一会话可以承载多个业务任务，S5 是新的业务任务而不是上一次任务的延续。

## 2. 链路步骤

| 步骤 | 谁 | 输入 | 可观察结果 | 结束条件 |
| --- | --- | --- | --- | --- |
| S0 提供输入 | 用户 | 一段需求文本 + 一个带表头的 CSV，放在用户选定的本地工作区 | 新的业务任务被接受（新 task_id、业务幂等键、初始 attempt），桌面出现该任务的状态条目 | 输入同时齐备 |
| S1 结构化 | 伙伴 | S0 的输入 | 成果卡：结构化结果 + 待确认问题清单，每条字段带来源标记 | 结果卡生成，问题清单可读 |
| S2 纠正 | 用户 | 对字段的修改、对问题的回答、补充的规则 | 任务在 waiting_user 中接受补充/纠正输入并继续；结果卡按纠正更新，被改字段标“用户确认”，旧结果不被覆盖 | 用户确认结果可用 |
| S3 提议 | 伙伴 | S2 的纠正内容 | 一条提议：把这次做法保存为可重复功能，附规则摘要与适用范围 | 用户看到提议 |
| S4 决定与发布 | 用户 + 伙伴 | 提议 | 接受只授权制作候选包；候选包依次 draft → testing → ready，独立验证通过、包哈希与拟发布版本一致、授权覆盖该版本与权限后才切 active；否则显示状态与失败原因，可修改或取消 | 出现一个 active 版本，或候选被取消 |
| S5 复用 | 用户 | 新的需求文本 + 新的同结构 CSV | 新业务任务（新 task_id、业务幂等键、初始 attempt）固定使用已发布的某个技能版本；结果结构与上次一致，已确认规则生效，缺失信息仍标待确认 | 新结果可核对 |

S1 与 S3/S4 采用服务端先给快照再持续推送事件的方式；页面显示的状态以最新快照为准，不靠推测进度。

S0 前置条件：需求文本与 CSV 必须同时具备。缺少其一属于输入不完整，链路不启动，返回输入错误（C01 的 `INVALID_INPUT`），不产出任何推测性结果，也不退化成“仅文本”的另一条链路。

任务身份（D1）：每个新的业务输入创建一个新任务，带自己的业务幂等键与初始 attempt；S2 的补充/纠正输入继续当前任务，不把每次输入都当成新的业务请求；同一业务任务的失败重试或中断恢复才创建新 attempt，旧输入与结果不被覆盖；网络重发同一业务请求沿用原幂等键，不创建重复任务。会话只用于界面归组，不代表任务边界。

## 3. 输入定义

| 输入 | 形式 | 约束 |
| --- | --- | --- |
| 需求文本 | 自由文本，来自用户粘贴或用户选取的本地文本文件 | 允许口语化、允许缺少要素；不做语言承诺之外的外语处理保证 |
| 条目 CSV | 文本文件，UTF-8，逗号分隔，首行为表头 | 允许缺列、允许空单元格、允许重复行；本次不解析 Excel 二进制、PDF、图片 |
| 工作区 | 用户在设备上选定并授权的目录 | 一个工作区一个写者；输入与成果只在该授权范围内读写 |
| 纠正内容 | 用户对字段的修改、对问题的回答、口述或书写的规则 | 只对该用户、该工作区生效；未确认的规则不写入功能 |
| 币种与含税口径 | 来自 CSV 中写明的币种列，或来自用户的明确确认 | 不存在地域默认值；不按客户所在地推断币种 |
| 新输入（S5） | 新的需求文本 + 结构与上次一致的 CSV | 作为新的业务任务提交（新 task_id、业务幂等键、初始 attempt），固定使用已发布的技能版本；结构不一致时按缺失信息规则处理，不静默套用 |

## 4. 可观察输出

### 4.1 结构化结果（成果卡）

| 输出字段 | 内容 | 必需 |
| --- | --- | --- |
| 需求摘要 | 一句话说明对方要什么 | 是 |
| 需求要素 | 交付物、时间、地点、特殊要求；不需要的要素标“该需求未提及” | 是 |
| 明细行 | 每行对应 CSV 一行：行号、名称、数量、单位、单价、币种、行小计 | 是 |
| 行小计与合计 | 由已知数量与单价按十进制定点语义算出，并记录公式与操作数字段引用；任一必需价格未知时对应金额为 null | 是 |
| 部分小计 | 只有部分行可计算时，给出已知部分的合计并标为部分小计，不冒充完整合计 | 是 |
| 字段来源标记 | 每条字段标注四类之一：输入（含文件与行号）/ 用户确认 / 确定性计算（含公式与操作数）/ 待确认 | 是 |
| 待确认问题清单 | 每条含：问题、针对哪个字段、为什么需要确认、该字段当前状态 | 是 |
| 缺字段 | 标为 null 与待确认，不用 0 或猜测值占位 | 是 |
| 执行信息 | 本次使用的执行器、费用来源、费用状态（已知金额或未知） | 是 |

来源标记是成果卡的一部分，不是内部注释：任何一条字段都必须能回答“它从哪里来”；确定性计算也要给出公式与操作数引用；没有来源的金额不得因为模型有把握就输出。已知的 0 与未知的 null 分开显示。混合币种不相加为一个总额，首版分别显示各行小计并提示无法给出单币种完整合计，不做自动换汇。未知的执行费用同样是 null。

### 4.2 保存提议（S3）

| 提议内容 | 说明 |
| --- | --- |
| 名称与用途 | 一句话说明这个功能做什么 |
| 适用输入 | 需求文本 + 与该次同结构的 CSV |
| 固化的规则 | 逐条列出从用户纠正中得到的规则（如币种取值来源），可解释、可拒绝 |
| 不固化的内容 | 上次的客户资料与具体金额不进入规则；规则只描述处理方式 |
| 输入/输出字段 | 该功能的输入字段与产出字段，含哪些字段允许缺失 |
| 版本与绑定 | 首个版本 v1；运行时绑定具体版本与包哈希 |

用户接受只授权制作候选包，不等于启用。候选包依次经历 draft → testing → ready；只有独立验证通过、包哈希与拟发布版本一致、且授权覆盖该版本与所需权限时，才切换 active 指针；缺少覆盖该版本的授权时先请求确认。验证失败或缺授权时显示候选状态与失败原因，用户可以修改或取消，S5 不会把它当成已启用功能。拒绝保存保留本次工作结果，不产生启用功能。载体沿用 SKILL.md + scripts + capability.json 的不可变版本包（C08）；物理存放位置由后续技能模块任务实现，本文不新建目录或公共接口。停用阻止后续自动选用该版本，不删除历史结果与规则来源，也不等价于取消正在执行的任务（取消按 C03 单独处理）。

## 5. 用户动作

| 动作 | 用户做什么 | 可观察效果 | 对应契约 |
| --- | --- | --- | --- |
| U1 提供输入 | 选定工作区，给出需求文本与 CSV | 每个新的业务输入创建一个新任务并进入排队/执行 | `POST /api/v1/tasks`（TaskBrief 携带 inputs 引用与幂等键） |
| U2 查看结果 | 打开成果卡 | 看到结构化结果、来源标记与待确认问题 | `GET /tasks/{id}` 快照；`artifact.ready` 事件 |
| U3 纠正 | 改字段、回答问题、补充规则 | 任务在 waiting_user 中接受补充输入并继续；需要重新执行时由服务协调 attempt；被改字段标“用户确认” | `POST /tasks/{id}/inputs` |
| U4 决定提议 | 接受或拒绝保存 | 接受 → 制作候选包，经验证与授权后才 active；拒绝 → 不保存，本次结果保留 | `approval.required` 事件与对应回执 |
| U5 再次运行 | 提供新文本与新 CSV | 新 task_id、业务幂等键与初始 attempt，固定使用已发布版本 | 同上，输入为新 artifacts |
| U6 停止或停用 | 取消当前运行，或停用已保存功能 | 取消按真实退出呈现；停用阻止后续自动选用，历史结果与来源记录保留 | `POST /tasks/{id}/cancel`；停用不删除历史 |

用户不必认识内部名词。任务详情可以显示实际执行器和费用来源。会话只用于界面归组：同一会话可包含多个业务任务；只有同一业务任务的重试或恢复才在任务内创建新 attempt。

## 6. 缺失信息、计算与来源规则

1. 允许确定性计算：行小计 = 数量 × 单价；同一已知币种下、明细完整时可以对行小计求和得到合计。计算使用十进制定点语义，不做浮点近似。
2. 计算必须记录来源：每个由计算得到的金额记录公式与操作数字段引用；没有来源的金额不输出。
3. 缺失不推测：价格、币种、含税口径缺失、为空或含义不明时标为 null 与待确认，不填猜测值。
4. 不猜价格、汇率与地域默认值：缺失价格不得由其他行、其他文档或历史结果推算；不按客户所在地推断币种；首版不做换汇、不做税率计算。
5. 部分可计算时给部分小计：只能算出部分行时，显示已知部分的合计并明确标为部分小计，不冒充完整合计。
6. 未知与零分开：未知金额与未知费用为 null，已知的 0 保留为 0。
7. 冲突要问：同名字段出现多个不同取值（如文本说一个价、CSV 里是另一个价）时列为待确认问题，不静默选取；显式新输入与已保存规则冲突时同样列问题，不静默覆盖输入。
8. 缺列按列处理：CSV 缺少整列时，该列在全部明细行统一标待确认，不逐行猜测补值。
9. 缺行不编造：文本提到但 CSV 中不存在的条目，作为问题提出，不生成新行。
10. 每个待确认字段都有对应问题：问题必须能回答“缺了什么、为什么要它、当前状态是什么”。
11. 未确认的规则不入库：用户在 S2 未明确确认的口径，不写入 S4 的功能；一次性字段值与以后复用的规则分开记录。

## 8. 排除范围（明确不做）

1. 无对外业务动作：不发送客户邮件或聊天消息，不写 CRM/ERP，不提交网页表单，不下单、不支付、不做报价承诺；已完成的消息草稿也不对外投递。
2. 无自动付款与自动承诺：不发起支付、下单、开票或对外报价承诺；金额只做整理与确定性计算，未知费用为 null。
3. 无持续屏幕采集：不截屏、不常驻录制、不推断未获授权的桌面活动；用户没有主动提供的内容不作为输入。
4. 单一用户、单一工作区、单一设备：无多用户协作、无团队共享、无跨用户或跨工作区读取。
5. 无语音输入输出、无浏览器自动化、无外部业务系统连接器。
6. 无技能市场与自动发布：不跨用户共享功能，不自动把候选包发布为 active；发布必须经过独立验证与授权覆盖，完整生命周期与版本迁移不在本链路内。
7. 不使用真实个人或客户资料：开发与验收样本一律为虚构资料（与 M00.1.02-A01 一致）。
8. 表格输入限带表头的 CSV 文本：不解析 Excel 二进制、PDF、图片或非文本表格。
9. 不新增金额功能：不做换汇、不做税率计算、不设地域默认币种或默认含税口径。
10. 不做性能与规模承诺：本链路不承诺大文件、并发或延迟指标，相关判断留到 M00 证据之后。

授权基础设施的边界（D5）：用户明确授权的模型推理、对象存储与沙箱属于基础设施，不算对外业务动作；但它们仍受 permission_grant、allowed_connections、cloud_fallback_allowed、数据范围与预算约束，不能以“基础设施”名义越过授权上传文件，没有云端授权不得自动回退云端。本批只做本地文档与虚构 JSON 样本，不需要也不授权任何实际云端模型、账号、支付或沙箱调用。

## 10. 架构裁定结论与移交

r1 的四个未决点已由 docs/handoff/DECISIONS-BATCH-001.md 关闭，结论如下：

1. 任务身份（D1）：S5 创建新的业务任务，使用新 task_id、业务幂等键与初始 attempt，并绑定已发布的技能版本与包哈希；attempt 只用于同一业务任务的重试与恢复。见第 2、5 节与 FLOW-A07。
2. 保存与启用（D2）：接受只授权制作候选包；必须经 draft → testing → ready、独立验证通过、包哈希一致、授权覆盖后才可以 active；不新增用户链路，载体沿用 SKILL.md + scripts + capability.json，物理位置留给后续技能任务。见第 4.2、8 节与 FLOW-A05。
3. 首版字段（D3）：沿用第 4.1 节最小字段，不增加税率计算、汇率转换与交期格式；币种与含税口径只来自明确输入或用户确认，不设地域默认值；样本的内部字段名与来源引用不是新的公共契约。见第 3、6 节。
4. 金额、来源与缺失（D4）：允许由已知数量与单价做确定性计算并记录操作数来源；金额为十进制定点；部分可计算时给部分小计；未知为 null，与已知 0 分开；混合币种不相加。见第 4.1、6 节与 FLOW-A03/A06。
5. 对外动作（D5）：排除的是客户邮件、聊天消息、CRM/ERP 写入、网页表单提交、下单、支付与报价承诺；用户授权的模型推理、对象存储与沙箱属于基础设施，但仍受授权与预算约束。见第 8 节与 FLOW-A02。

移交独立验收者（D6）：M00.1.02 的 expected.json 只含 normal/missing 的公开期望；M00.1.03 的 holdout.json 只放预留输入、不含任何预期结果，其预期由独立验收者在本批提交后生成并保管。开发者不能声称对该文件真正未见，也不把它当作演示或代码生成示例。
