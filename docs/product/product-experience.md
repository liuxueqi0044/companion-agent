## 1. 产品承诺与默认行为

用户在一个连续的个人空间里与同一个AI相处：表达需求、交付任务、得到帮助、纠正它，再让它逐渐改变外观和做事方式。

第一条完整体验：进入空间 → 告诉它一个偏好 → 改变空间 → 交付一件真实工作 → 看见执行过程 → 得到可核对成果 → 保留下次能继续使用的东西。

第二条核心体验：用户选择允许主动联系 → AI根据后续互动判断值得关心的事情 → 安排有时效的一次跟进 → 到时重新判断 → 给用户发一条适当的消息 → 用户回应、忽略、调整或关闭。

### 默认行为

| 项目 | 默认 | 用户在哪里改变 |
| --- | --- | --- |
| 长期记忆 | 开启；首次清楚告知 | 头像/名字 → 记忆 |
| AI主动联系 | 关闭 | 头像/名字 → 主动联系；轻量引导 |
| 系统级通知 | 未授权，按需请求 | 更多 → 设置 → 通知 |
| 任务结果 | 总在应用内保存和展示 | 近况 → 任务/消息 |
| 用户明确安排的提醒 | 只执行所明确安排的那一项 | 主动联系 → 我的提醒 |
| 初始外观 | 一个精简的默认空间 | 改变这里；直接对话 |
| 任务过程 | 复杂任务自动展开，允许收起 | 正在做的事 → 展开过程 |
| 思考展示 | 能力可用时显示模型公开内容的最近片段 | 执行区域 → 思考内容 |
| 自动采集电脑上下文 | 无默认授权 | 以后逐个连接具体来源 |
| 改名、称呼、明确语气设置 | 保留至用户修改或重置 | 头像/名字 → 关于这个AI |

“主动联系关闭”限制的是AI自行决定新发起的问候、建议和跟进。用户自己交办的任务回执、明确设置的提醒独立管理，界面使用不同名称，避免一个总开关产生歧义。

第一版优先帮助经常在电脑上工作、希望有私人空间和重复任务帮助的个人用户。陪伴与做事沿同一条交互关系发生，不要求用户选择“工作模式”或“陪伴模式”。

## 2. 页面结构及固定入口

### 2.1 首页上的长期入口

桌面顶部保留一条很轻的宿主栏，主内容为可定制空间。

| 位置 | 控件 | 点击结果 |
| --- | --- | --- |
| 左上 | 小头像 + AI名字 + 下拉提示 | 打开“我的AI”面板 |
| 右上 | 近况；有未读时小圆点 | 打开近况面板，默认消息 |
| 右上最末 | 更多 ⋯ | 设置、恢复默认界面、停止正在进行的任务、帮助 |
| 主内容 | 伙伴呈现/对话/任务/成果 | 随当前活动展开 |
| 底部 | 输入框、添加材料、发送 | 发起对话或动作 |

顶部宿主入口始终可访问。生成界面可以改变主内容的布局和表达，不会把记忆控制、停止、费用、授权和恢复入口覆盖掉。自定义界面可增加自己的快捷入口，但最终指向同一份设置与状态。

上表是默认空间的布局，不要求每个生成界面长成相同导航结构。自定义版本可把宿主控制收拢为一个轻量入口，由可信宿主提供展开与恢复；用户仍能找到这些控制。自由改写的范围涵盖主空间的风格、组件、布局和交互，不止替换颜色与背景。

### 2.2 “我的AI”面板

从上到下：

1. AI头像、名字、一句当前角色/表达描述，点击进入“关于这个AI”。
2. **记忆**，右侧状态“开启/关闭”。
3. **主动联系**，右侧状态“未开启/已开启/暂停至……”。
4. **改变这里**，回到主输入并准备修改当前空间。
5. **我的工具**，查看保留的能力与小应用。

“关于这个AI”可以修改名字、对用户的称呼、表达偏好。角色表达、外观和工具独立变化，个人AI身份保持稳定。

### 2.3 “近况”面板

三个标签：**消息 / 任务 / 作品**。

- 消息：主动联系、提醒、需要用户决定的事项和任务完成摘要。
- 任务：进行中、需要处理、已结束。点击回到对应执行过程。
- 作品：用户保留的文件、界面版本和小工具；系统临时中间文件默认折叠。

会话历史入口位于主对话的“历史”按钮或“更多 → 会话记录”；工作结果不要求通过搜索旧对话才能找到。

## 3. 第一次打开与模型连接

### 3.1 首次进入顺序

**第一屏：可以直接进入的欢迎页。** 展示默认空间缩略构图、产品名称和一句话：“慢慢把我变成适合你的样子。”一个主按钮“进入我的空间”。

按钮附近有简短说明：“长期记忆默认开启，可随时关闭；主动联系默认关闭。”两个文字入口可在进入前改变对应开关；不要求先填写一张个人资料表。

**第二屏：进入个人空间。** AI用简短文字问：“我该怎么称呼你？”可直接回答，也可以跳过并开始工作。没有设置称呼时用自然的无称呼表达。

**第三步：提供一个可忽略的启发。** “你可以交给我一件事，也可以先改变这里。”示例短句帮助理解用途，点击只把示例填入输入框，由用户继续编辑或发送；这些示例不对应预制模板。

首次欢迎只出现一次。记忆/主动联系默认状态持续可查，后续不重复遮挡首页。

### 3.2 没有可用模型连接时

欢迎页仍能查看；需要模型的第一次发送保留原输入，出现就近的“连接一个模型服务”入口，说明连接后可以继续这条请求。

点击 → P14“模型与连接” → 选择实际已支持的服务 → 输入或选择凭据 → 明确点击验证/连接 → 返回原对话并由用户继续发送。凭据字段隐藏内容；验证若会发请求或产生费用，按钮附近事先说明。失败保留用户输入并给出可读原因。

产品以后若提供已配置的托管服务，可以省去此步。设计不假设现阶段已经提供免费额度或任何订阅账号兼容能力，也不列出尚不可用的伪连接选项。

## 4. 首页、对话与重新打开

### 4.1 空闲状态

主内容显示用户的空间、伙伴呈现和一个输入框。初次可以有一句欢迎；没有需要说明的新情况时，保留安静空间。用户随时可以隐藏伙伴形象，只保留文字或自己的工具。

输入框提示：“想聊聊，还是一起做点什么？”下方/附近只在合适时出现一条启发，如“试着让我改改这里”。启发可以关闭。

### 4.2 发送消息

点击输入框 → 输入文字或添加材料 → 发送。文件会先显示可移除的材料条目，读取失败在发送前明确标示。发送后立即保留用户消息，展示真实的连接/处理中状态。

AI根据需求选择直接回应、询问必要信息、提出行动、开始授权内的执行，或安排用户明确要求的提醒。用户不需要先选择执行器。

进入复杂任务时，原对话保留在上下文中，主区域展开P03。普通聊天保持较窄的阅读宽度。任务内部的过程信息不挤占全部日常聊天历史。

新对话从对话顶部的轻量按钮进入。另有“临时对话”选项，其标题持续标示：本次不读取/写入长期记忆，也不自动安排后续联系；用户明确要求的一次提醒可以建立，并留下可见回执。临时对话的数据保留规则在入口说明，不宣称“不留下任何痕迹”。

### 4.3 重新打开

打开 → 恢复当前个人空间版本、同一身份与明确设置 → 读取真实任务和未读消息 → 根据实际状态显示近况。

- 有进行中任务：显示简短入口“还有一件事在进行”，点击展开P03。
- 有待决定事项：优先显示一条能采取行动的提示。
- 有已完成成果：显示成果入口，不强制打开长过程。
- 有主动联系：右上近况出现未读点；用户可点开。
- 无新事项：回到安静空间，不虚构工作活动。

收起窗口与退出应用区别明确。只有后台仍运行且能力支持时任务继续；完全退出或电脑休眠后的恢复状态按实际运行结果显示。

## 5. 大型任务执行区域

### 5.1 页面布局

复杂任务启动后，P03成为主要内容。桌面建议占可用主区域的60%–75%，任务内容宽度随窗口适配，不做只能容纳两行的小卡片。窄窗口可铺满主内容，顶部保留返回入口。

从上到下：

1. **任务标题和当前动作**：例如“核对三份报价”“正在检查第二份材料的数量”。
2. **用户控制区**：停止、补充要求、收起。需要用户决定时在此附近突出决定入口。
3. **步骤概览**：初步计划、已完成、进行中、等待用户；计划改变保留简短说明。
4. **执行过程**：当前动作、公开思考内容、工具行动和中间成果分区呈现。
5. **成果区**：已有可用结果及时出现，标明临时/最终。

典型信息结构：

```text
核对三份材料                         收起   停止
正在检查第二份材料的数量              已核对 1 / 3 份

读取材料  ✓     整理内容  ✓     核对差异  ●     输出结果

现在正在做
正在比较这两处数量，发现一处单位不同。

模型提供的思考摘要              展开全部 / 收起
……供应商实际提供的可展示内容……

实际操作
✓ 已读取：材料 A
✓ 已生成：待核对清单
● 正在核对：材料 B 第……处

已有成果                            打开预览
[ 可使用的清单或文件 ]

[补充一句要求……]
```

### 5.2 思考内容与实际操作

供应商明确提供、允许展示的思考摘要或思考内容按实际能力流式呈现，标记“模型提供”。模型没有提供时，不生成伪造的内部独白；系统仍展示依据真实事件生成的“执行说明”，并明确标记来源。

公开思考内容不作为完成证明。步骤状态由实际工具调用与回执驱动；失败、等待、重试、结束要与运行状态一致。原始密钥、凭据和无关私人资料不会进入展示日志。开发调试信息收在“详情”，默认使用人能理解的动作名称。

默认展开当前步骤和最近一段思考；用户可以展开全部并滚动阅读。用户主动向上阅读时停止自动滚动，出现“回到最新进度”。长内容可折叠，已完成步骤仍可回看。

有确定计数时显示“已处理2/3份”；没有可靠分母时显示当前步骤和等待时间，不编造百分比。AI调整计划时允许步骤变化，以“发现了……，增加一步……”解释。

### 5.3 中途补充、停止、切换任务

- 补充要求：用户发送后立即出现回执，“已采用”“当前步骤结束后处理”或“这会改变目标，需要确认”。不能只显示消息已送达。
- 停止：按钮点击后显示“正在停止”。只有执行器确认/可核查状态后才显示已停止；已生成成果继续可访问。
- 结果未知：显示“连接中断，正在核对执行结果”或等待用户显式核对，不直接宣布失败或自动重做外部动作。
- 切任务：目标任务快照加载完成前，旧内容标为过期且不可用于取消/重试等操作；新旧回复不会串到一起。
- 收起：任务变成空间里的简洁状态条；点击恢复同一任务。Esc或关闭侧栏不等于停止任务。

### 5.4 完成与失败

成功时成果上移成为重点，提供“打开”“继续修改”“留下这个做法”等相关动作。执行过程保留在可展开区域。

失败时显示失败步骤、已有成果和可行下一步；只提供确实能做的重试/补充/恢复。未完成的任务不会产生庆祝完成动效。

## 6. 长期记忆

### 6.1 精确点击路径

**左上头像/名字 → 记忆 → 记忆列表。** 面板顶部显示主开关和当前状态，下面是“记忆范围”“搜索”“添加一条”。用户无需进入通用设置深处。

列表按内容组织：称呼与表达偏好、工作习惯、用户选择记住的事情。当前任务临时信息和AI自行安排的短期跟进上下文不混在长期记忆里。

用户在设置中明确填写的名字、称呼和表达规则，可在此作为“明确设置”引用显示，点击跳到原设置；不复制成另一份自动记忆。关闭自动记忆后，这些用户亲自配置的内容继续生效，界面说明二者区别。

每条列表显示：一句自然语言记忆、来源类型、更新时间；点击进入P07。

### 6.2 记忆详情

详情显示：

- 记住的内容。
- 来源：“你在某次对话中明确告诉我”或“从这几次互动中总结”；可回到来源。
- 若存在不确定推测，显示待确认，不把它标成用户明确事实。
- 编辑、忘记、限制这类记忆三个动作。

“编辑” → 原地多行输入 → 保存/取消。保存后立即影响后续检索；AI用一句话确认，不重复展示整套技术过程。

“添加一条” → 用户写一句话 → 保存。用户也可以直接说“记住我喜欢……”，得到可点击的记忆回执。

### 6.3 定制记忆范围

点击“记忆范围”可开关工作习惯、表达偏好、长期目标等类别，也可以写自然语言规则：“只记工作相关内容”“不要记私人聊天”。规则有可读摘要，用户能编辑、删除。

涉及临时情绪、健康或亲密生活的内容，不因一次谈话自动固化为长期人格标签；明确要求记住时按要求处理。主动关心可以依赖已授权、短期保留的跟进上下文。

记忆变化有轻量反馈，例如消息旁“已记住 · 查看/撤销”。批量或频繁提取不会持续打断对话。

### 6.4 关闭与重新开启

点击顶部开关关闭 → 立即停止后续长期记忆读取和新写入，包括尚未落库的自动提取工作。面板说明：“长期记忆已暂停，原有记忆仍保留。当前对话仍可继续理解。”

已经发给模型的上下文无法事后撤回；界面另提供“开始临时对话”，从下一次请求建立不含长期记忆的新上下文。关闭记忆不自动删除任务执行所需记录或用户主动设置的名称/外观。

关闭时重新检查未发送的自动跟进。仅依赖现已停用的长期记忆、又没有单独获准保留的短期上下文的计划，取消或等待用户补充；不能把旧长期记忆复制到跟进笔记以绕过关闭。当前对话中的明确提醒可继续按其单独授权运行。

重新开启 → 从仍保留、未删除且符合当前范围的记忆继续。关闭期间的对话不会被自动补录；若用户希望整理那段内容，再明确提出。

### 6.5 忘记与清空

单条“忘记”默认同时取消由该内容衍生、尚未发送的自动跟进，并阻止从同一来源自动重新学回。界面回执说明这两项效果。

原聊天与长期记忆分开管理：若用户只忘记记忆，原对话可保留供自己查看，但不能被后台提取重新建立这条记忆。详情可另行选择删除来源对话，并说明可能影响整段记录。

“清空长期记忆”位于列表底部的次级操作，提供一次明确确认，列出影响；不同时删除文件、任务和工具。已经发送的消息与已经发生的动作不会被假称撤回。

## 7. 主动联系：核心体验

### 7.1 默认关闭与轻量引导

首次进入只说明默认关闭，不弹出系统通知权限请求。用户在普通互动后适合了解功能时，在对话末尾出现一次小提示：

> 希望我偶尔主动联系你吗？我可以根据之后的互动，在合适的时候跟进一件事，或问问你的近况。时间和频率都由你决定。
>
> **允许主动联系**　**暂时不用**

用户正处于情绪表达中时，先回应当下需要；不在脆弱时刻把开启功能或购买服务当作关心的前提。用户选择暂时不用后，不在连续会话里反复提示；仍可从“我的AI → 主动联系”自行开启。

这段引导用于产品内的主动联系授权，与操作系统允许弹通知分开。

### 7.2 开启流程

点击“允许主动联系” → 打开一个轻量设置面板，显示：

- **什么时候**：默认当地时间09:00–21:00；显示实际采用的时区，可改。
- **多频繁**：建议默认自动主动联系每天最多1次。此为产品建议值，可改为更少、每周几次或用户明确约定的频率。
- **可以聊什么**：工作后续、日常安排、近况关心。开启页清楚列出，用户可移除任何类别。
- **从哪里看到**：应用内消息始终可用；桌面通知按需授权。

按钮“按这些设置开启”。用户已经明确说“每天晚上可以问问我近况”时，可以直接形成对应设置回执，不再要求填一张重复表单。

用户的明确自然语言限制高于默认建议。授权内的每一次普通跟进不再逐条询问批准；新增主题、渠道或明显超出约定范围时再询问。

### 7.3 AI怎样自主安排一次关心

情境：主动联系已开启，用户在聊天中提到：“最近工作很难，今天挺难受的。”

1. AI先在当前对话回应。模型根据完整语境判断是否值得稍后再联系，可以选择不安排。
2. 若判断适合，提出内部跟进计划：来源互动、简短目的、预计时段、有效期、允许的渠道和取消条件。
3. 产品检查这个计划是否处于用户允许的主题、时间、频率和预算内；通过后持久保存。
4. 不在当前回应下预告下一条主动消息，不说“我两点半会再问你”，不显示自动计划的倒计时或待发送卡片。时间由模型在用户允许的时段内决定，普通首页和对话也不暴露这份内部计划。
5. 到期时模型基于获准保留的必要上下文重新判断：用户是否已说情况改善？是否刚聊过同一件事？是否更改偏好？这次消息是否仍有用？
6. 合适才生成并发送，例如：“前面你说今天挺难熬的，现在稍微好一点了吗？想聊的话，我在这里。”
7. 用户回复后回到原主题相关的对话。忽略一次问候不会自动导致连续追问；同一件事默认一次跟进。

这一机制允许模型选择时机和表达。主题选择、安静时段、频率、关闭与删除边界由用户控制；不会通过固定关键词命中就必发一条模板问候。

AI在计划里保存主题和必要上下文，到发送时再形成措辞，避免几天前写好的话在情况改变后照发。已解决、过期或上下文不足时可以取消，并在安排记录中说明状态。

### 7.4 用户在哪里看、怎么点

**左上头像/名字 → 主动联系。** 默认面板只有开关、允许时段、频率、话题和暂停；不展示自动计划列表或下一条消息时间。

用户自己明确交办的定时事项放在“我的提醒”中，显示时间、重复规则和取消入口。这类提醒需要清楚确认，不能因“惊喜”设计而隐藏用户交办结果。

自动消息收到之后，提供“为什么联系我”“这类事情少问一点”“这个话题别主动问”。用户也可以随时直接说“今天别问项目”“暂停到明天”。需要查看、删除为跟进保留的短期说明时，从联系管理进入；默认只展示主题和信息来源，不主动展示发送时间。用户明确询问某次计划时可如实回答，不能为了惊喜欺骗用户。

开发诊断接口可读取内部计划以核对时效、取消和恢复，不作为产品首页、普通对话或默认设置面板的数据源。

### 7.5 用户可以怎样定制

自然语言与设置页面等价：

- “工作上你可以主动一点，私人事情等我说。”
- “晚上十点以后别发消息。”
- “我没有回复的话，不用再问。”
- “今天先安静一下。”
- “明天上午再问问我那个项目。”
- “这个话题我不想再被提醒了。”

系统将明确意图转成可读规则并回执，缺少会影响行为的时间/范围才补问。语气偏好与主动频率分开，用户改成活泼语气不等于授权增加消息。

### 7.6 关闭、暂停和一次性提醒

主开关关闭后，停止新的AI自主跟进安排；已有尚未发送的自动跟进取消，包括等待生成和等待投递的项目。发送前再次核对授权版本，尽量阻止关闭后的竞态发送；已经交付外部渠道的消息不能保证撤回，记录真实状态。

“暂停至明天”暂缓自动联系；恢复时检查时效，过期问候直接作废，不集中补发。

用户明确说“明早提醒我”属于单次授权：即使主动联系总开关关闭，仍可创建这条提醒，并说明“仅安排这一次，主动联系仍关闭”。用户明确安排的提醒在关闭自动联系时保持，界面提供“同时取消已安排提醒”的独立选择。

“每天晚上总结当天工作”属于用户明确交办的重复任务，按约定重复，不要求打开AI自主联系。回执显示重复规则、下次时间、需要的数据和停止入口；资料或权限不足时说明缺口。每次任务结果仍受用户的通知渠道与安静时段设置控制。

### 7.7 记忆与主动联系的组合

| 长期记忆 | 主动联系 | 行为 |
| --- | --- | --- |
| 开 | 关 | 正常使用记忆，AI不自行发起后续联系 |
| 开 | 开 | 在授权范围使用记忆与互动来源形成跟进 |
| 关 | 开 | 不读取/新增长期记忆；只依据本次/之后互动及已授权短期跟进笔记联系 |
| 关 | 关 | 使用当前对话上下文；无自动长期记忆、无自主跟进；明确的一次提醒仍单独成立 |

“记忆关、主动联系开”时，P08必须说明：“为完成你允许的跟进，会暂时保存必要说明；你可在联系管理中查看和删除。”临时笔记有到期清理，不回流为长期人格事实。默认不超过跟进有效期，建议单次自动计划最长7天；需要更长时由用户明确安排。这里说明数据用途，不预告某一条消息的发送时机。

如果用户说“不要保存任何关于这件事的内容”，同时取消依赖该内容的跟进。收到跟进后用户要求忘记，也要阻止该来源重新建立未来跟进。

## 8. 消息、通知、时区与离线

### 8.1 收到消息

用户在应用内：近况增加未读点，当前主内容顶部可以出现一条轻量提示。复杂任务正全屏展开时不抢焦点；需要用户做决定的任务提示优先。

用户在其他应用：只有操作系统通知已授权且符合安静时段/频率策略时弹出通知。默认锁屏摘要使用“你的AI给你留了一条消息”，不直接显示情绪、健康或私人关系内容。用户可显式选择显示摘要。

点击通知 → 打开个人空间 → 定位到该条消息及相关对话。消息保留“为什么联系我”“少问这类事情”“关闭主动联系”的次级入口。标为已读不代表用户同意了任何动作。

### 8.2 三种独立控制

1. **AI主动联系**：AI是否能自主决定联系。
2. **任务通知与明确提醒**：用户交办事项的结果/时间提醒。
3. **系统投递权限**：是否能在应用外显示通知、声音或锁屏摘要。

关闭系统通知仍能在应用内查看；关闭主动联系不隐藏任务结果。通知投递不自动授权AI向其他人发消息。

### 8.3 投递可靠性

同一消息以稳定标识去重；重试通知投递不重新生成多条问候。收件箱是消息记录来源，操作系统弹窗是投递形式。提供“未能弹出通知，但消息已保存”等真实状态。

模型无法调用或预算不足时，保留安排并按时效判断稍后处理或过期；不伪造模型已完成一次主动判断。用户明确写好的固定提醒可以不依赖再次生成。

### 8.4 电脑休眠/退出与云端

首版本地运行：P08显示“仅在这台设备能够运行时送达”。收起窗口且后台运行可以继续；休眠、关机或完全退出不保证准时。界面不能把本地调度包装成全天云端服务。

恢复后，明确时间已错过的提醒显示“已错过”；情境问候先重新判断，过期不补发。用户正在另一个会话谈同一件事时，可取消重复问候。

云端是后续运行方式，接入后再标示“设备离线时也可处理”。每次按用户时区安排；设备时区变化时检查固定本地时间规则，必要时给用户可修改的摘要。

## 9. AI修改自己的界面

### 9.1 进入

直接说“把这里改成……”；或点“我的AI → 改变这里”，输入框聚焦并显示当前版本缩略预览。可选“参考社区作品”入口只在社区功能实际可用后出现。

用户描述风格、布局、角色或交互。AI读取当前实现并改代码；不要求从几种官方模板里选，也不为每次调整强制另开一个Coding Agent。

### 9.2 修改到生效

发送要求 → 形成候选并显示适量过程 → 自动构建/检查 → 在已验证隔离能力内预览 → 就绪后应用到当前空间。

用户明确要求的授权内可逆修改，通过后可直接生效并显示“已改好 · 撤销 / 继续调整”。用户要求先看看，或涉及未提交输入无法保留等情况，提供预览并由用户决定采用。新增权限单独通过宿主处理，不能用外观修改顺带授权。

等待改版期间旧空间继续可用。切换保留当前任务、对话、草稿和能兼容的视图状态。无法保留的草稿先保存或说明处理办法，不静默丢弃。

### 9.3 恢复与版本

“撤销”回到上一可用界面；“我的AI → 改变这里 → 历史版本”可预览并恢复指定版本。恢复界面不回退任务执行、权限撤销或已删除记忆。

坏包、超时、崩溃保留旧版，并显示“这版暂时没能启用，当前空间仍可使用”。“更多 → 恢复默认界面”始终由稳定宿主提供。

真正的模型代码运行必须经过原生隔离等独立验证；当前工程中的静态候选与可信fixture不能用来冒充完整的对话改版功能。

## 10. 能力成长与私人小工具

用户完成类似任务后，AI可提出一个有具体收益的建议：“要把这个做法留下来吗？下次把材料放进来就能继续用。”主动建议是否跨会话发送仍受主动联系授权控制。

点击/口头同意 → AI整理流程、复用现有能力或编写缺失部分 → 用适用样本和新输入验证 → 展示用途、输入、结果与权限 → 在用户授权范围保存。

保存成功后，“我的AI → 我的工具”出现这个能力；用户可以把它放到空间里，也可以直接用自然语言调用。布局可由AI编写代码，工具业务版本独立管理。

工具详情：用途、如何输入、最近使用、修改要求、停用/删除、版本回退。运行中的任务固定实际使用版本，修改工具不会偷偷换掉一半执行逻辑。

如果一次工作不值得形成工具，AI直接交付结果。成长记录应反映真实保留下来的能力，不用虚构经验等级。

## 11. 分享与采用

从空间版本或工具详情点击“分享” → 选择要公开的外观/工具/明确选中的角色设定 → 系统用虚构数据生成预览 → 用户查看最终内容清单 → 确认导出或发布。

私人记忆、原对话、任务材料、授权和凭据不被打包。源码也可能包含私人常量或资源，需要检查最终选入内容，不能只靠目录排除就宣称已脱敏。

接收者先看预览，再“带到我的空间”；创建独立来源与版本关系，保留接收者自己的身份和设置。安装需要的连接与权限重新获取；后续继续对AI说要怎样改。

初期先做本地作品导出/导入与虚构预览，公开链接和社区后续接入。可选的改造前后展示只捕捉已选入、适合公开的空间，不自动录制整个私人桌面。

## 12. 视觉与操作标准

### 12.1 默认空间方向

一个温暖、克制的初始空间。阅读清楚、间距舒适、低饱和强调色；角色呈现可小可无，用户可继续改造。最终配色、字体、角色和版式在正式视觉阶段确定。

闲时空间疏朗；聊天时形成舒适的阅读列；做事时展开宽执行区域；完成后强调可使用的成果。四种状态沿同一页面变化，转场帮助用户理解发生了什么。

### 12.2 控件与布局

- 普通常用目标建议至少40×40逻辑像素；危险操作有文字，不只用难辨认图标。
- 面板关闭后焦点回到原入口，输入草稿保留。
- 桌面记忆/主动联系面板建议宽360–420；内容较多时可展开为工作区域。
- 窄窗口面板占满主内容，顶部固定返回；主输入与停止入口不被挤出可访问区域。
- 状态不能只用颜色表达，配合文本与图标；支持系统字体缩放。

### 12.3 动效与键盘

状态变化使用短、克制的过渡；工作进度只依据真实事件。尊重减少动态效果设置。没有真实执行时不持续播放“忙碌”动画。

Enter发送、Shift+Enter换行；可在设置切换发送习惯。Esc关闭当前浮层，永远不偷偷取消任务。停止任务有明确按钮和可聚焦入口；修改/删除后提供可读回执。

任务进度对辅助技术做节制播报，逐字思考流不持续抢读。按钮有名称，原文预览与状态变化可通过键盘访问。

## 13. 异常和恢复设计

| 情况 | 用户看见什么 | 可做什么 |
| --- | --- | --- |
| 模型未连接 | 输入保留；就近连接入口 | 连接后继续 |
| 模型请求失败 | 本次回应失败，已提交任务状态独立 | 重试回应/查看真实任务 |
| 凭据或额度问题 | 可理解的连接问题，不回显密钥 | 打开模型与连接 |
| 长期记忆关闭 | 顶部明确关闭；旧条目可查看管理 | 开启/编辑/清空/临时对话 |
| 主动联系关闭 | 未开启说明；已安排的一次提醒独立列出 | 开启/管理提醒 |
| 通知权限拒绝 | 消息在应用内可查 | 打开系统设置说明 |
| 设备离线错过时机 | 已错过/已过期 | 查看或重新安排 |
| 任务停止中 | 正在停止，仍可查看已有成果 | 等待回执/核对状态 |
| 执行回执未知 | 结果待核对 | 显式核对；不自动重复动作 |
| 选择任务加载中 | 目标加载中，旧内容标过期 | 等待/切换；不对旧任务误操作 |
| 界面改版失败 | 旧空间保留，错误摘要 | 再改/恢复默认 |
| 不支持某种能力 | 清楚说明缺少的连接/能力 | 选择现有可行办法 |

新一次输入、切任务或改版后，旧异步回复只能更新自己的交互/任务记录，不能把当前页面退回旧状态。失败记录与中间成果属于用户可查历史；普通首页不常驻长错误日志。

## 14. 首版范围和工程关系

### P0：需要形成产品闭环

- 统一个人空间入口、对话与真实任务关联。
- 稳定身份与显式偏好。
- 长期记忆默认开、可查改关删，来源与排除规则清楚。
- 主动联系默认关、轻量授权、AI提出跟进、持久安排、到期复核、收件箱及取消闭环。
- 一条真实本地任务链与足够大的执行区域、真实状态/成果展示。
- 代码定制与版本恢复的可靠链路；生成源码运行须补足隔离验收。

首版主动联系可以先在本机后台运行，诚实展示设备在线限制；用户开启的授权与计划管理必须是真实功能，不能只做一个开关和假消息演示。

### P1：接在核心体验之后

桌面通知完善、多设备云端调度、私人小工具积累、本地分享/Fork、更多实际连接器。按真实使用场景逐项接入。

### P2：依赖反馈再扩大

公开社区、语音通话/TTS、手机专属体验、更多角色表现、多租户商业运营。用户可以定制的自由度是持续方向，初始实现支持范围要清楚。

### 与当前工程的关系

已有个人身份/显式偏好不等于长期语义记忆已完成；现有本地任务/桥接实验不等于对话主控已集成；当前代码包候选不等于生成界面可安全运行。主动联系、持久收件箱与跟进调度目前需要新增产品集成。

复用现有memory/agent/scheduler适配方向，先确认其实际可用能力。产品层负责授权、用户可见安排和投递记录；避免同时维护两套竞争语义记忆或两套执行调度权威。模型决定是否跟进，运行服务负责可靠地保存、唤醒、校验和投递。

本轮设计不授予开发过程额外模型请求额度、不启动真实定时消息、不改变现有批次验收状态。真实语义质量、时间安排适宜性、原生隔离和产品视觉须各自验收。

## 15. 体验验收场景

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| UX-01 | 新用户首次进入 | 能直接进入空间；明确知道记忆开、主动联系关 |
| UX-02 | 两次点击找记忆 | 左上头像→记忆即可到主开关和列表 |
| UX-03 | 修改一条记忆 | 可查看来源、编辑，后续按新内容使用 |
| UX-04 | 关闭记忆 | 后续读取/提取停用，待写入工作不会悄悄落库 |
| UX-05 | 忘记来源 | 删除后不从相同来源自动学回；关联自动跟进取消 |
| UX-06 | 关闭记忆但保留设置 | 名字/外观等明确设置保持，说明与实际一致 |
| UX-07 | 主动联系未开 | 普通谈话不会产生AI自主消息；轻量引导可跳过 |
| UX-08 | 开启主动联系 | 可读时区/时段/频率/主题，授权持久且可改 |
| UX-09 | 情绪相关跟进 | 先回应当下；模型可安排一次后续关心，来源可查 |
| UX-10 | 到期前情况改善 | 重新判断，取消或调整旧问候，不机械照发 |
| UX-11 | 不回复跟进 | 不自动连续追问，不因未回复升级频率 |
| UX-12 | 自主时机与控制 | 普通对话不预告自动联系；我的提醒可管理明确交办事项；“别再问”取消对应自动计划 |
| UX-13 | 关闭自动联系 | 旧自动队列和待生成/待投递项失效；发送前再次核对 |
| UX-14 | 一次性提醒 | 总开关关时仍可按明确请求安排，仅授权本项 |
| UX-15 | 记忆关、主动开 | 短期跟进上下文可见、有期限，不写回长期记忆 |
| UX-16 | 桌面通知拒绝 | 仍可在收件箱看到，拒绝通知不导致丢消息 |
| UX-17 | 休眠后恢复 | 不谎称准点；过期问候不集中补发 |
| UX-18 | 复杂任务进行 | 主区域清楚显示当前动作、步骤和已有成果 |
| UX-19 | 展示思考 | 公开模型内容与执行说明标明来源，无伪造推理或完成 |
| UX-20 | 用户上翻过程 | 不被新内容强制滚回；可返回最新进度 |
| UX-21 | 停止与未知结果 | 状态依据真实回执，不把点击停止当作取消完成 |
| UX-22 | 切换任务 | pending时不误操作旧任务，迟到回执不覆盖新视图 |
| UX-23 | 自定义界面 | AI能修改代码，用户无需选官方模板 |
| UX-24 | 改版失败/回退 | 旧界面、草稿、身份、任务仍可用；恢复入口不丢失 |
| UX-25 | 保留一项能力 | 下次可找到、复用和修改，输入输出与权限可解释 |
| UX-26 | 分享作品 | 审阅最终清单；私人数据、记忆与授权不随作品传播 |
| UX-27 | 窄屏与键盘 | 记忆、主动控制和停止入口可用；焦点和草稿不丢 |
| UX-28 | 原型与真功能区分 | 未接通能力明确说明，不用模拟数据声称已上线 |

评估重点：首次成功完成一件事、用户是否保留定制、任务结果是否被实际使用、主动消息是否有用且不过度打扰、记忆纠正是否生效。主动功能同时观察关闭、取消和负反馈，不能仅用消息回复率或在线时长判断价值。
