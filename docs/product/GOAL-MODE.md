# 目标模式与 Coding Agent

输入框旁点“目标模式”，或直接输入“目标模式：……”（也支持 `/goal ...`）。例如附上 CSV 后说：“目标模式：先按客户汇总金额，再根据实际结果写报告，每项都核对后再继续。”普通聊天的入口与行为不变。

主控先提出任务与验收标准，按依赖分派执行者；执行者完成后提交真实成果，由主控逐项核对，可退回修改。任务卡显示主控、执行和验收步骤，以及各任务的轮次、依赖与结论。模型验收是一种质量控制，不代表独立人工验收，也不能保证模型永远判断正确。

默认使用 `deepseek-v4-pro` 指挥/验收，`deepseek-v4-flash` 执行。可在启动前配置 `PERSONAL_AI_DIRECTOR_MODEL`、`PERSONAL_AI_WORKER_MODEL`、`PERSONAL_AI_REVIEWER_MODEL`；三者允许相同。所有请求串行，网络失败不自动重试。目标每连续 24 次判断暂停保存，手动继续最多 192 步；最多 12 个任务、每任务 4 次派工。连续三次同类调度失败也会暂停。

本机有 Claude Code 时，可说：“目标模式：请分派 Claude Code 编写一个小工具，保存源码和说明，再读取实际文件核对。”自动寻找 `%USERPROFILE%/.local/bin/claude.exe`，其他位置用 `PERSONAL_AI_CLAUDE` 指定；CLI 不随便携包分发。使用同一 DeepSeek 加密凭据，独立目录和配置，不使用原 Claude 登录、钩子、插件或本机 Codex 账号。已实测官方 CLI 2.1.215。

当前 Claude 执行器只开放任务目录内的文件工具，最多 12 文件/128 KiB；JS、Python、JSON 有宿主语法检查。没有通用 Shell、依赖安装或程序行为测试。生成的文件可以下载；复杂项目运行测试需要后续受控执行器。一次 CLI 启动可能包含多次串行 DeepSeek 请求，记录分别计数。

处理中可停止，程序重启后不会自动重发模型请求。网络失败可从原任务继续；明确停止的任务需要新请求重新授权。工具限制、上下文截断和未执行的检查会保留在记录里，模型不能覆盖这些事实。
