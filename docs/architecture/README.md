# 桌面 AI 伙伴：架构与开发交付包

版本：0.2 · 调研日期：2026-09-23 · 状态：架构设计，尚未实现或运行产品集成测试。

**交给执行模型开发，请从新版 [小任务执行包](../execution/START-HERE.md) 开始。** 原来的 55 项是计划层，已细化为 156 张带文件边界、共享接口、实现步骤和验收条件的任务卡。辅助派工工具不会启动模型或执行产品任务。

产品目标：一个有持续记忆、可主动交流、能完成工作，并能把用户反复做的事情变成可复用功能的桌面 AI 伙伴。面向全球独立工作者，首阶段验证小规模个人用户。

本包包含 12 个模块、55 项开发任务，其中 6 项接入验证、44 项首版任务、5 项后续扩展。任务按依赖安排，不要求一个小团队同时维护所有组件。

**主选方案：Hermes 管长期状态和日常协作；Codex 是工程执行引擎；Electron + Vue 承载自己的产品界面。** 这两个执行框架分工明确，每个任务只有一个负责者。模型品牌与框架选择分开决定。

## 开发原则

- 直接采用：模型工具循环、子任务执行、会话历史、技能格式、基础组件、语音模型、浏览器驱动、数据库、队列和沙箱。
- 适配开发：认证映射、事件转换、沙箱交接、成果登记、技能版本与发布、通知偏好。
- 自主设计：界面与交互、用户工作流程的改进体验、结果呈现和品牌角色。
- 每次引入新组件，先证明现有组件不能满足需求。避免为相同用途同时部署两套记忆库、调度器或主 Agent 框架。
- 先完成“实际任务 → 用户纠正 → 学成一个功能 → 换新输入再次成功”的完整链路，再增加复杂角色和持续语音。

## 第一个可交付版本

用户拖入需求文件和一份表格 → AI 整理结构化结果及回复草稿 → 用户纠正字段/格式 → AI 记住纠正 → 提议保存为功能 → Codex 复用现有库实现缺失步骤并验证 → 新文件再次处理 → 云端完成后通知用户。

首版只生成可审查的成果和草稿。新增外部系统写入能力时再加入对应授权和执行回执；这是一条模块扩展路径，不影响先交付核心产品。

## 当前结论的证据边界

本轮核查了官方文档、仓库说明、部分源码配置和许可证。Hermes 与 AIRI 记录了所查看的提交 SHA。尚未安装这些项目、调用付费模型、验证互操作、购买服务、创建 GitHub 项目或部署产品。文档中所有性能目标、工期和通过标准均是拟定的工程目标，不是实测结果。

开工第一阶段就是验证最容易影响选型的几条链路：Hermes 的会话/中断/隔离；Hermes 与 Codex 的交接；用户已有 Codex/Claude Code 的官方接入；AIRI 组件与自有界面的复用成本。
