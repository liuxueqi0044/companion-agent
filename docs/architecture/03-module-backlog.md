# 模块拆分与开发顺序

**执行版已细化为 [156 张小任务卡](../execution/START-HERE.md)。** 本文的 55 项保留为上层计划；实际派工请使用执行版依赖、文件白名单和验收规则。

设计日期：2026-09-23。共 12 个模块、55 个可验收任务；全部尚未开始。

P0 为选型验证；P1 为首个小规模内测版本；P2 为有需求后再做的扩展。模块编号是职责划分，不表示必须做完整个模块才开始下一个。以每项列出的依赖为准。

机器可读版本：[backlog.json](backlog.json)。字段、接口和状态含义见[接口契约](05-contracts.md)。

## 执行方式

每次给开发者或执行模型一项明确任务：附对应契约、样例、责任目录和验收条件。小任务完成后提交产物与实际验证证据，由主负责人集成；不能只凭工作者声称成功就勾选完成。多个开发者不能覆盖彼此改动。

建议先贯通一条很窄的竖向链路，再扩充功能。支付、复杂角色与持续语音不阻挡技术演示；基本身份隔离、费用记录、取消和成果验证从第一条链路就存在。

| 模块 | 目标 | 责任目录 |
| --- | --- | --- |
| M00 关键接入验证与开发基线 | 先证实复用路线可落地，再承诺排期。 | `docs/decisions/`、`tests/spikes/`、`packages/contracts/` |

| M04 外部 Agent 联动 | 让用户已有 Codex、Claude Code 与伙伴协作。 | `adapters/agents/`、`apps/desktop/main/agent-bridge/` |

| M11 测试、观测、部署与发布 | 从第一个接口起建立可诊断、可回退的交付过程。 | `tests/acceptance/`、`infra/`、`services/control/observability/` |

## 发布里程碑

| 阶段 | 完成标志 |
| --- | --- |
| 接入可行 | M00 全部完成；明确双运行时与官方订阅的实际限制，调整排期 |
| 第一条工作链路 | 登录 → 任务 → 一个真实执行器 → 可打开的成果；任务与费用可查 |
| 学会一个功能 | M07.5 通过：纠正后生成可重复能力，新输入能直接使用 |
| 连接既有工具 | M04.4 通过：Codex/Claude、离线、额度与费用切换可用 |
| 内测候选 | M11.4 通过：故障、隔离、恢复、记忆删除和技能回退有证据 |
| 商业判断 | M11.5 完成：用户复用、持续使用与支付意愿有实际数据 |
| 扩展 | 需求成立再执行 P2；不以增加模型或角色数量代替产品验证 |

## M00 · 关键接入验证与开发基线

先证实复用路线可落地，再承诺排期。

**责任边界：** 只做短验证和契约，不把验证脚本变成未经评审的生产服务。

**目录：** `docs/decisions/`、`tests/spikes/`、`packages/contracts/`

### M00.1 冻结首条用户链路和验收样本 · P0

- 前置：无。
- 输入：产品目标、首批用户访谈假设。
- 交付：文本需求 + CSV 样例、正确结果、纠正记录及未见样本。
- 复用：现有文档工具、CSV 标准库。
- 验收：主链路可用一句话说明；正常、缺失字段与错误输入有期望结果；明确首版不包含持续语音和公开技能市场。

### M00.2 建立依赖与许可证基线 · P0

- 前置：M00.1。
- 输入：本交付包来源清单。
- 交付：候选版本、来源、LICENSE/NOTICE、资产登记及升级策略。
- 复用：各项目官方仓库、现成包管理器锁文件。
- 验收：区分开源代码与云服务；记录实际选定版本及间接依赖；Claude Code 单列官方集成条件。

### M00.3 验证 Hermes 与云端工程执行路径 · P0

- 前置：M00.2。
- 输入：两个隔离用户目录、同一任务样本、受限测试预算。
- 交付：Runs/取消/中断/隔离记录，原生 Codex runtime 与直接 SDK 路径选择。
- 复用：Hermes API/目标/委派、Hermes Codex runtime、Codex App Server。
- 验收：不同用户不能互读文件；取消和进程退出状态真实；记录原生桥缺失能力；不需要重写核心循环即可回收工程成果。

### M00.4 验证 AIRI 组件抽取与桌面壳 · P0

- 前置：M00.2。
- 输入：AIRI 指定提交和目标系统。
- 交付：最小 Electron/Vue 构建及组件取舍记录。
- 复用：AIRI、Electron、Vue。
- 验收：选中的组件可独立构建；列出实际仓库内依赖和素材许可；抽取代价高时保留成熟桌面壳并停止迁移该组件。

### M00.5 验证用户官方 Agent 与订阅接入 · P0

- 前置：M00.2。
- 输入：用户自行授权的测试账号/官方程序、当前官方文档。
- 交付：Codex 和 Claude Code 各一份登录、运行、取消、计费来源证据。
- 复用：Codex App Server、未修改的 Claude Code 官方 SDK/CLI。
- 验收：官方登录完成且产品不接触订阅 token；成果可回收；不能读取额度时标未知；记录版本和规则核查日期。

### M00.6 冻结接口草案并重估范围 · P0

- 前置：M00.3、M00.4、M00.5。
- 输入：所有接入验证、05-contracts.md。
- 交付：v1 Schema、能力矩阵、选型 ADR 与调整后的工期。
- 复用：Pydantic、JSON Schema、上游生成类型。
- 验收：失败路线有可执行替代方案；原生协议字段与产品字段分开；首版所需能力全部有验证入口。

## M01 · 产品体验与桌面界面

让用户自然地聊天、看成果、重复使用功能。

**责任边界：** 不在渲染进程直接操作本机 shell、供应商凭据和产品数据库。

**目录：** `apps/desktop/renderer/`、`packages/ui/`

### M01.1 确定设计语言与核心交互 · P1

- 前置：M00.1、M00.4。
- 输入：真实用户链路、桌面技术验证。
- 交付：设计变量、伙伴/工作区布局、状态文案与交互原型。
- 复用：shadcn-vue、VueUse、选定 AIRI 组件。
- 验收：聊天、任务、成果、功能、记忆及连接入口可找到；异常状态有清晰下一步；键盘操作和对比度可用。

### M01.2 实现桌面壳和受限系统桥 · P1

- 前置：M00.6、M01.1。
- 输入：UI 原型和桥接权限定义。
- 交付：窗口、托盘、单实例、通知入口和类型化 IPC。
- 复用：Electron、Vue。
- 验收：渲染进程不具备 Node 权限；窗口关闭/退出语义清楚；所有 IPC 校验来源和参数。

### M01.3 接入会话和任务状态 · P1

- 前置：M01.2、M03.2。
- 输入：ProductTaskAPI、RunEvent。
- 交付：流式对话、任务卡、取消与重连快照。
- 复用：VueUse、既有 API 客户端。
- 验收：重连无重复消息；执行进度与最终验收分开；等待设备/额度/用户均有真实状态。

### M01.4 接入成果和功能页面 · P1

- 前置：M01.3、M05.3、M07.4。
- 输入：ArtifactRef、已发布技能 Schema。
- 交付：安全预览、下载、功能输入表单与再次运行入口。
- 复用：JSON Forms、可信表格/文件组件。
- 验收：新输入可再次运行；恶意 HTML 不进入主 UI 执行；运行结果可追溯到技能版本。

### M01.5 完成首次使用与可用性验证 · P1

- 前置：M01.4、M04.4、M06.3、M08.3。
- 输入：完整首版链路和连接设置。
- 交付：简短引导、示例任务、错误恢复文案及用户走查记录。
- 复用：现有 UI 组件、系统无障碍支持。
- 验收：新用户能连接一个 Agent 并完成样例；不要求理解框架术语；关闭主动问候和查看费用来源都容易找到。

## M02 · 身份、数据与产品控制服务

提供可靠的多用户任务入口和持久产品状态。

**责任边界：** 产品保存任务投影；不另建一套 Agent 推理循环或重复历史库。

**目录：** `services/control/identity/`、`services/control/tasks/`、`infra/database/`

### M02.1 接入身份和工作区 · P1

- 前置：M00.6。
- 输入：身份/工作区 Schema。
- 交付：登录、令牌验证、用户/设备/工作区表。
- 复用：Supabase Auth、FastAPI。
- 验收：服务端从可信会话取得用户身份；过期和撤销会话失效；用户无法指定别人所有者身份。

### M02.2 实现数据与对象隔离 · P1

- 前置：M02.1。
- 输入：数据归属表、保留策略。
- 交付：数据库迁移、RLS、对象路径及限时访问。
- 复用：PostgreSQL、Supabase Storage/RLS。
- 验收：跨用户读写被拒绝；高权限后端也校验归属；私有文件不产生永久公开地址。

### M02.3 实现任务队列和持久事件 · P1

- 前置：M02.2、M11.1。
- 输入：TaskBrief/RunEvent Schema。
- 交付：幂等提交、PGMQ 消费者、状态投影、事件游标和死信记录。
- 复用：PGMQ、FastAPI、PostgreSQL。
- 验收：重复投递不重复启动；相同幂等键不同内容冲突；消费者崩溃后可对账；游标过期返回刷新快照信号。

### M02.4 提供隔离用户运行单元 · P1

- 前置：M02.2、M00.3。
- 输入：已验证 Hermes 启动配置。
- 交付：用户进程/卷生命周期、私网访问、备份入口。
- 复用：Hermes profiles、标准容器运行工具。
- 验收：每用户独立可写目录；任意代码不能触及宿主服务；重启后能定位原会话和中断任务。

## M03 · 主控 Agent 与长期任务

复用强模型规划、委派和验收能力，保证产品状态真实。

**责任边界：** 不做硬编码行业流程引擎；只约束权限、资源、状态与结果。

**目录：** `adapters/hermes/`、`services/control/runtime/`

### M03.1 封装 Hermes 运行接口 · P1

- 前置：M02.4、M00.6。
- 输入：固定版本 API 和产品契约。
- 交付：SupervisorRuntime 的会话、启动、停止及能力探测。
- 复用：Hermes Runs/Sessions API。
- 验收：适配器通过契约测试；原生错误保留可诊断信息；不依赖解析人类终端文本。

### M03.2 接入主会话及事件映射 · P1

- 前置：M03.1、M02.3。
- 输入：会话映射与队列消息。
- 交付：任务到原生 run 的绑定、标准事件与恢复查询。
- 复用：Hermes SSE/会话历史。
- 验收：UI 断开不终止云任务；原生回合结束不伪报任务验收通过；上游短期事件丢失可由快照恢复重要状态。

### M03.3 配置模型分工与预算入口 · P1

- 前置：M03.2、M10.1。
- 输入：任务复杂度提示、两档模型配置。
- 交付：强主控、便宜工作者和确定性执行规则。
- 复用：Hermes delegate_task、现有提供商配置。
- 验收：简单任务可直接完成；普通委派不假装支持每任务模型参数；预算检查覆盖主控、子任务及评审。

### M03.4 加入目标、检查点与恢复 · P1

- 前置：M03.3、M05.2。
- 输入：长期任务状态和故障样例。
- 交付：目标运行、检查点、超时和中断对账。
- 复用：Hermes goals、必要时 Hermes Kanban。
- 验收：子进程退出不被标继续运行；系统进程约束有验证；无法确认的外部写入不自动重做；已有成果不丢失。

### M03.5 实现结果验收与受限重试 · P1

- 前置：M03.4、M05.3。
- 输入：完成条件、成果和验证报告。
- 交付：机械校验 + 语义验收、失败反馈、有限重试。
- 复用：JSON Schema、现有测试工具、强模型评审。
- 验收：缺失文件和错误 Schema 必须失败；语义评审引用实际产物；重试受预算和次数限制；保留未解决项。

## M04 · 外部 Agent 联动

让用户已有 Codex、Claude Code 与伙伴协作。

**责任边界：** 凭据留在官方客户端；不改写其认证、不将订阅转成共享代理。

**目录：** `adapters/agents/`、`apps/desktop/main/agent-bridge/`

### M04.1 实现连接注册与设备配对 · P1

- 前置：M00.6、M01.2、M02.1。
- 输入：AgentConnection、设备配对协议。
- 交付：执行器注册、白名单、能力和在线状态。
- 复用：Electron 主进程、上游版本探测。
- 验收：只启动已登记程序；配对可撤销；不上传完整本机环境或凭据文件；费用来源可见。

### M04.2 接入本机 Codex · P1

- 前置：M04.1、M03.2、M05.1。
- 输入：已验证 Codex 版本、TaskBrief。
- 交付：官方登录、stdio 运行、事件、授权、取消及文件回收。
- 复用：Codex App Server。
- 验收：用户通过官方流程登录；同一任务不重复开 run；官方授权请求绑定原动作；产物完整且取消有实际证据。

### M04.3 接入本机 Claude Code · P1

- 前置：M04.2。
- 输入：同一契约、M00.5 接入证据。
- 交付：Claude 适配器及能力差异说明。
- 复用：未修改的 Claude Code、官方 SDK/程序化接口。
- 验收：前端无需另写任务页面；用户自有认证和使用账单；不支持功能返回明确原因；官方程序和认证方式保持原样。

### M04.4 加入离线、额度与付费路由 · P1

- 前置：M04.3、M02.3、M10.2。
- 输入：设备心跳、额度结果、用户费用偏好。
- 交付：等待、到期、断线对账和有授权的执行器切换。
- 复用：PGMQ、官方状态接口。
- 验收：过期任务不上线补跑；不能读取额度显示未知；换计费来源须已有授权；同一工作区仅一个写任务。

### M04.5 按真实需求接第三种 ACP Agent · P2

- 前置：M04.4。
- 输入：第三种执行器需求、许可核查。
- 交付：ACP 客户端及现成适配器组合。
- 复用：ACP 官方协议/SDK、已有 Agent ACP 适配器。
- 验收：认证、成果、取消逐项验证；能力差异可见；不能为统一接口捏造恢复支持。

### M04.6 向外暴露已保存功能 · P2

- 前置：M04.4、M07.4。
- 输入：可调用技能、授权范围。
- 交付：产品 MCP 的运行功能/查询成果入口。
- 复用：MCP 官方 SDK。
- 验收：外部 Agent 只能操作授权用户和技能；结果包含任务 ID；长任务可查状态且不重复执行。

## M05 · 工具、沙箱与成果

提供可复用执行工具和可信成果交接。

**责任边界：** 生成代码在隔离环境，不能接触产品主机、计费和发布权限。

**目录：** `integrations/tools/`、`services/control/artifacts/`

### M05.1 实现工具权限入口 · P1

- 前置：M02.2、M00.6。
- 输入：工具 Schema、权限范围和动作账本。
- 交付：MCP 工具网关、审批关联、输入验证和回执。
- 复用：MCP Python SDK、Pydantic。
- 验收：工具参数变更使旧审批失效；跨用户资源被拒绝；读写动作区分；日志脱敏。

### M05.2 接入云端执行沙箱 · P1

- 前置：M05.1、M10.1。
- 输入：E2B 账户配置、资源和费用限制。
- 交付：沙箱创建、输入挂载、执行、停止与清理工具。
- 复用：E2B SDK、所选官方工程运行时。
- 验收：超时与取消释放资源；不注入产品主密钥；文件仅落授权范围；记录沙箱费用和残留资源。

### M05.3 建立成果登记和安全预览 · P1

- 前置：M05.2、M02.2。
- 输入：执行输出和 ArtifactRef。
- 交付：上传、哈希校验、下载、预览及保留期。
- 复用：Supabase Storage、既有文件解析/预览组件。
- 验收：缺失或被篡改成果校验失败；生成 HTML/SVG 无宿主权限；用户可导出自己的成果。

### M05.4 接入首条业务工具链 · P1

- 前置：M05.3。
- 输入：M00.1 文本和 CSV 样本。
- 交付：读取、结构化、转换、输出工具；确需浏览器时接已有驱动。

## M06 · 人格、长期记忆与工作记录

记住人的偏好与纠正，让用户能理解和控制记忆。

**责任边界：** 不增加第二套长期记忆引擎；不把工作者的猜测自动当成用户事实。

**目录：** `adapters/hermes/memory/`、`services/control/memory/`、`apps/desktop/renderer/memory/`

- 验收：人格不随执行器切换；事实与推断区分；没有观测依据不声称看见用户行为。

### M06.3 实现查看、修改与忘记 · P1

- 验收：删除后当前会话快照更新；被删除来源不重新进入检索；解释只删偏好与同时删历史的差异；跨用户隔离。

### M06.4 验证长期一致性与检索 · P1

## M08 · 主动消息与调度

让伙伴在有价值的时刻主动出现，而且容易控制。

**责任边界：** 一个定时任务只由一个调度器触发；模型不直接绕过用户通知偏好。

**目录：** `services/control/notifications/`、`adapters/hermes/jobs/`

### M08.1 定义通知偏好和候选策略 · P1

- 前置：M02.2、M06.1。
- 输入：用户时区、安静时段、消息类别。
- 交付：候选 Schema、频率/去重/到期规则。
- 复用：Pydantic、PostgreSQL。
- 验收：任务通知与问候分别可控；默认规则不声称未授权观测；无变化不重复唤醒强模型。

### M08.2 接入既有定时任务 · P1

- 前置：M08.1、M03.4。
- 输入：Hermes Jobs 和运行进程约束。
- 交付：创建/暂停/删除映射、重启和错过执行规则。
- 复用：Hermes cron/heartbeat、script-only 检查。
- 验收：调度进程存活要求有监测；重启不重复执行同一事件；修改时区行为明确；停止任务不继续唤醒。

### M08.3 实现收件箱与桌面通知 · P1

- 前置：M08.2、M01.3。
- 输入：已通过策略的消息候选。
- 交付：持久收件箱、投递记录、桌面提示及点击定位。
- 复用：PGMQ、Electron 通知。
- 验收：离线后消息仍可查；过期消息不补打扰；投递与已读不混淆；关闭声音或问候立即生效。

### M08.4 加入可解释的主动改进建议 · P1

- 前置：M08.3、M07.5。
- 输入：已授权的工作摘要和改进证据。
- 交付：低频建议、接受/拒绝反馈及静默策略。
- 复用：Hermes 主控、现有通知策略。
- 验收：建议引用实际工作依据；用户拒绝后减少同类提示；不以情绪施压诱导继续使用；关闭陪伴不影响工作功能。

## M10 · 成本、额度与商业化

让每次任务的费用有归属，让产品能测出真实毛利。

**责任边界：** 不把订阅未知费用写成零，不自建支付收单，也不默认转售官方 Agent 使用量。

**目录：** `services/control/usage/`、`services/control/billing/`

### M10.1 建立全链路用量账本 · P1

- 前置：M02.2、M00.6。
- 输入：供应商用量字段、执行器和沙箱引用。
- 交付：usage_events、幂等计量和付款方分类。
- 复用：PostgreSQL、提供商实际回执、Langfuse 社区能力。
- 验收：规划/执行/评审/重试都计入；未知金额用 null；用户订阅与平台 API 分开；同一回执不重复入账。

### M10.2 实施任务和账户预算 · P1

- 前置：M10.1、M02.3。
- 输入：预算策略、并行执行及供应商限额。
- 交付：预留/结算、限额停止、新付费来源授权规则。
- 复用：PostgreSQL 事务、执行器原生限额信息。
- 验收：并行任务不各自花掉全部预算；不再启动超限新调用；取消尾部费用可查；不静默切 API 账单。

### M10.3 设计并接入产品付费方案 · P1

- 前置：M10.2、M07.5。
- 输入：实际使用成本、目标用户所在市场和访谈。
- 交付：服务费用与推理来源分开呈现的套餐、支付与权益映射。
- 复用：所选支付服务的官方 SDK/托管收银台、现有权限表。
- 验收：价格来自成本数据而非拍脑袋；支付回调幂等并验签；退款/停订行为明确；官方 Agent 路径不代收转售其用量。

### M10.4 建立商业验证指标 · P1

- 前置：M10.3、M08.4。
- 输入：匿名化产品事件和成本记录。
- 交付：复用率、成功任务成本、人工介入、留存和付费意愿看板。
- 复用：PostgreSQL 查询、Langfuse 现有数据。
- 验收：区分演示吸引力与持续使用；订阅账单缺失不计假毛利；看板不包含原始私密内容。

## M11 · 测试、观测、部署与发布

从第一个接口起建立可诊断、可回退的交付过程。

**责任边界：** 本模块从早期开始，不是最后才做安全和恢复。

**目录：** `tests/acceptance/`、`infra/`、`services/control/observability/`

### M11.1 建立契约测试和持续集成 · P1

- 前置：M00.6。
- 输入：Schema、样本、目录责任边界。
- 交付：类型检查、接口模拟、固定样本和构建流水线。
- 复用：现有测试框架、包管理器、CI 服务。
- 验收：验证真实状态和业务结果；不只测试实现自证；密钥与用户数据不进仓库；模块变更有兼容性检查。

### M11.2 接入观测与故障定位 · P1

- 前置：M03.2、M10.1。
- 输入：任务/attempt/trace ID 与脱敏规则。
- 交付：结构化日志、错误链、耗时/费用关联和运行健康检查。
- 复用：Langfuse 社区功能、结构化日志。
- 验收：一个失败任务能追到执行器版本和产物；日志默认不含 token/原始私密文件；调度/设备状态异常可发现。

### M11.3 建立可回退的内测部署 · P1

- 前置：M02.4、M05.2、M11.2。
- 输入：固定依赖、桌面构建和数据库迁移。
- 交付：部署脚本、备份恢复、运行升级与桌面签名更新方案。
- 复用：标准容器工具、托管 Supabase/E2B、Electron 发布工具。
- 验收：恢复备份实际演练；上游升级先过兼容测试；生成技能无发布主程序权限；正式分发前完成签名验证。

### M11.4 完成核心发布验收 · P1

- 前置：M01.5、M03.5、M04.4、M06.4、M07.5、M08.4、M10.2、M11.3。
- 输入：完整产品和故障注入场景。
- 交付：端到端报告、已知限制和上线/暂缓结论。
- 复用：统一契约测试、真实执行器、固定验收集。
- 验收：黄金链路新输入通过；跨用户攻击失败；取消/断线/额度/到期真实；技能可回退；记忆可删；重复投递无重复副作用。

### M11.5 小规模用户验证并决定后续投入 · P1

- 前置：M11.4、M10.4。
- 输入：内测者实际使用、授权采集的指标和反馈。
- 交付：继续/收缩/停止判断，下一阶段优先级。
- 复用：现有成本与任务数据、用户访谈。
- 验收：验证用户是否反复使用学成的功能；衡量连接已有 Agent 是否降低流失；有留存和付费证据后才增加语音/市场/多区域平台。
