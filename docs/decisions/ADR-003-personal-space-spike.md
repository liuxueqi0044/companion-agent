# ADR-003 · Personal AI 增补实验边界与视觉归属

状态：2026-09-24架构裁定，BATCH-011范围冻结；尚未实现或验收。上位方向为ADR-002 r2。

1. 用户明确初始前端视觉由交接方架构师亲自设计实现。执行方仅实现不带产品设计决策的代码包、状态与替换底座，附朴素工程测试页。产品入口温暖、克制、有陪伴感、简洁；布局/配色/角色和正式组件后续由架构师接入。技术测试页面不得升级为产品默认页面。
2. 先采用三文件HTML/CSS/JS可编辑包和可信的确定性装配，既不做预设主题目录，也不在本批引入新的编译依赖。代码可自由写布局/交互，宿主接口限制权限而非外观。未来Vue编译和资源包需另行验证，不假称本批支持所有框架。
3. BATCH-011是独立增补实验轨道，满足原M00.0工具链、M00.4.01选型这些已accepted前置。156卡与hash冻结、原gate保持；实验不计原卡完成。正式产品契约仍以Python/Pydantic单源为准，实验TS接口只存在tests/spikes，正式化前迁移并生成Schema/TS。
4. 对生成代码的信任边界分两阶段：本批通过可信人工fixture验证状态机与桥，模型候选只存文件。生产级原生进程/网络/超时隔离未实测之前，任何模型包都不允许执行或装入宿主。iframe/CSP和静态校验不能替代敌对代码沙箱，后续专批验证Electron/E2B适配，再打开受控生成包预览。
5. 本地宿主持有虚构个人身份、输入与任务投影，不新建语义记忆/权限权威。源码候选/发布指针/状态持久化分离，候选失败不破坏当前空间。继承C08不可变与base revision思想，但不宣称已实现C08正式端口。
6. 用户已授权本项目使用提供的DeepSeek key。凭据保存于本机DPAPI CurrentUser文件，位置仅在派工中引用。授权限定BATCH-011最多两次串行请求、无重试、虚构材料、本地保守估算合计≤US$0.05；不使用当前OpenAI账户。不以凭据已存储声称API有效或有余额。
7. 复用既有Node/Vue/Vite/TS与旧窄客户端的限额思路；不新增通用Agent、执行器、模板引擎或微服务。官方MCP Apps仍是后续生产桥候选，本批不安装SDK或自称兼容MCP Apps。

具体字段、接口、写集和验收见BATCH-011；该派工冻结且只读。后续正式化必须：独立复核实验→补生产隔离验证→迁移公共契约/受影响任务与hash→接入架构师原创初始界面→验证真实对话改版。不能把候选文件生成当作这条完整链路通过。
