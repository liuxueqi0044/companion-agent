# ADR-009 · 整个前端可替换，默认界面只是一个实现

状态：目标已确认；下文代码审查记录的是 CORE-010 结束时的基线。CORE-011 已实现资源接口、按装载实例隔离的视图、同 SDK 的默认 UI、多文件完整根界面包与恢复闭环，详见 [CORE-011](../development/CORE-011.md)。CORE-013 增加 Electron 原生载体与授权窗口 SDK；自然语言完整界面作者、社区级不可信代码隔离仍未完成，历史表格与报告不追改。原生实现和实际验证边界见 [CORE-013](../development/CORE-013.md)。

## 1. 必须满足的产品含义

用户所说的定制包括整个前端的结构、交互、组件、路由和表现形态。现有默认首页、聊天输入、导航、记忆面板、任务卡都不是永久固定的产品框架。用户的 AI 可以隐藏、替换、重组这些视图，编写截然不同的前端，乃至把主窗口收起，使用桌面上的小精灵。

我们交付的是可替换的前端运行与能力接口，以及一个默认实现。具体作品由用户和其 AI 创作；不建设官方模板目录，不把“书房封面”“桌宠样式”“工作台皮肤”逐个制作当作平台完成度。

延续 ADR-002 的可编程界面方向，并明确：稳定宿主是稳定的权限、执行和数据边界，不等于必须始终显示的顶栏或输入框。权限决定不能由普通界面代码改写，日常控制的视觉和位置可以改写。

## 2. 本次代码审查

| 层次 | 实际状态 | 判断 |
| --- | --- | --- |
| Python 业务服务和数据库 | 身份、记忆、任务及结果已经独立于 Vue | 保留；换界面不应重建业务数据 |
| Node execution/runtime | 模型、工具和串行执行已有实现，可无视觉测试 | 保留；对外操作入口需去除当前选中页面的隐含前提 |
| application 和 web API | 固定 PANELS；work.start/stop/result 依赖 selectedTurn/current panel；部分列表读取会改变会话选择 | 还不是面向任意界面的稳定能力接口 |
| 当前默认 Vue UI | app.mjs 同时处理会话 ID、局部缓存、上传、请求、面板状态及整套渲染；布局直接写在 render 函数 | 工程师可以修改，但不适合直接作为任意生成前端的公共 SDK |
| CORE-010 canvas | 只挂到欢迎位置；无聊天、记忆、任务桥；模型提示词明确限制为首页装饰与本地交互 | 无法实现用户要求的深度定制；不是模型本身不会写 UI |
| 不可变代码包/预览/版本 | 有源码、哈希、封存、预览、显式启用与回退 | 复用机制，扩展包与装载契约；不能把三文件/64 KiB 试验上限当永久架构 |
| 原生桌面载体 | apps/desktop/package.json 和 renderer 是历史空壳；当前产品在 localhost 浏览器运行；无 main/preload/托盘集成 | 真正桌面小精灵尚不支持，不能用浏览器内图形冒充 |

关键证据：personal-space/app.mjs；product/application/index.mjs 的 PANELS、selectedWorkTurn、snapshot；product/runtime/index.mjs 的视图绑定；product/web/server.mjs 的 selected/action 路由；product/space/package.mjs 的 SPACE_PROMPT；personal-space/canvas.mjs 的只读存活消息。

结论：底座可复用，无需推倒项目；前端替换边界需要一次实质重构，不能只放宽提示词或把 iframe 拉满屏。

## 3. 目标边界

| 层 | 职责 | AI 可以改什么 |
| --- | --- | --- |
| 业务核心 | 身份、记忆、模型调用、任务、授权、真实事件 | 通过现有能力请求使用，不直接改库/密钥/授权实现 |
| 版本化前端 SDK | 按稳定 ID 读取数据、订阅事件、请求动作；严格验证归属和实例 | 用这些能力自由写界面；不向作者暴露通用 IPC、Node 或 shell |
| 界面运行宿主 | 包装载、实例隔离、生命周期、窗口能力、授权和恢复 | 在获准范围申请窗口形态与行为，不能自行扩权 |
| 可替换前端包 | 页面、组件、样式、交互、角色表现、本地视图状态 | 全部可改；默认 UI 也是遵循同一契约的普通包 |
| 恢复与授权通道 | 无需当前 UI 或模型仍能停用坏包、恢复默认和处理授权 | 不能移除其能力；不要求固定出现在主界面上 |

浏览器载体可使用宿主管理的恢复路由；桌面载体使用托盘/快捷键/受信任窗口。用户完全隐藏主界面时仍可恢复。新的 UI 不必复制默认导航，也不必呈现默认聊天气泡、卡片或面板。

## 4. 必须先补的接口

以下是职责草案，尚不是已冻结的方法名称：

- 会话：按 conversationId 获取消息、发送新消息、订阅回复片段。客户端发送同一 commandId 的重连不能重复请求。
- 任务：按 taskId/attemptId 获取进度、结果和请求停止，操作带所有者、实例与授权绑定；不要求先打开默认聊天页面。
- 记忆与偏好：通过已有权威入口读取/编辑用户授权的内容，不把 UI 状态当长期记忆，也不给界面整个数据库。
- 事件：按资源订阅并携带游标和代次，界面重装可恢复；同一工作台可显示多个任务，不能共享单一全局 selectedTurn 来决定它们的身份。
- UI 本地状态：按包/用户/实例命名空间保存草稿、选项、布局。换版不得丢失未发出的输入；不把这些字段混入人格或记忆。
- 窗口：尺寸、位置、装饰、透明、置顶、拖动、可交互区域等受支持能力。它们是组合能力，不是“桌宠/工作台”两个固定模板编号。

迁移任务操作时，要以显式资源绑定替代 selected guard，不能直接删掉防错任务/错代次的校验。切换 UI 不得取消后台任务；界面组件卸载不能销毁共享 runtime。

## 5. 代码作者的工作流

提供读取当前前端源码、SDK 类型与示例、虚构数据、独立编辑空间、构建、预览、错误反馈、启用和回退的工具。作者可以是用户当前主控，也可以是其 Coding Agent；不额外创造第二个通用 Agent 框架，不把某一个 DeepSeek 提示词变成产品架构。

包保存可编辑多文件源码、资源、依赖锁、构建入口、构建产物和 SDK 兼容范围。先支持项目现有 Vue/Vite 工具链，复用构建器；这不是限制界面布局。当前三文件画布可保留为小包兼容路径，不能成为所有前端的强制表达格式。

改 CSS、改组件、重组路由、移除聊天页面都由作者实现。平台验收构建、契约、权限和生命周期，不要求所有作品长得像当前默认界面。

## 6. 私人数据与桌面边界

CORE-010 的零数据 iframe 不足以直接升级为能显示私人聊天的正式壳。增加 SDK 同时必须验证数据投影、导航/网络控制、实例绑定、权限撤销、崩溃/卡死恢复；不能把整个 runtime 或会话 token 直接交给生成代码。

默认聊天也必须走同一 SDK。仅把它列为“可信例外”，却让其他包永远无法发消息或看任务，仍然没有实现可替换架构。真正必要的授权决定和恢复走宿主通道，已经授予的日常操作不应每点一次都多一个确认框。

桌面小精灵需要原生窗口能力；当前选型的 Electron 提供无边框与透明窗口，但存在平台限制，不能用模型生成页面代替原生集成。透明、置顶、点击穿透、焦点和恢复要在 Windows 实测。保留 contextIsolation、sandbox 与受限 preload 方法，不能通过关闭安全设置换取自由度。

参考官方文档：[窗口样式](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)、[上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。这些证明可采用的平台机制，不证明本项目已完成桌面实现。

## 7. 开发顺序与验收门槛

1. **资源能力接口**：从默认页面选择中解耦读取/动作，复用原业务服务与执行槽。测试工作台同时观察两项任务，停止明确指定的那一项；一个视图的导航不影响另一视图。
2. **前端 SDK + 默认 UI 迁移**：剥离 app.mjs 业务编排，默认 UI 也只用公开能力和自身视图状态。其聊天、记忆、真实任务、取消和断线恢复均保持通过。
3. **完整前端包宿主**：复用源码封存/预览/回退，扩展多文件构建与完整根视图装载。验证没有默认顶栏/输入框的另一测试界面也能真实聊天、查看任务；换版不中断任务、不丢草稿或记忆。
4. **原生载体**：Windows 原生透明/无边框窗口、托盘与恢复机制。验收主窗口隐藏后，独立小视图仍连同一 AI、接收真实状态，退出坏界面后可以恢复默认。
5. **作者工具接入**：模型读取当前源码和 SDK，按用户自然语言改造任意组件或整包。用两种结构完全不同的临时测试作品验证自由度，不把它们做成产品必选模板。

不设未经拆分验证的工期或完成百分比。该顺序改变后续优先级：先解除固定 UI 边界，再扩展画布样式、聊天改版入口或社区分享。
