# CORE-008：取消产品次数额度，分离对话与工具过程

用户授权：取消原本地预算，继续复用 DeepSeek；不增加并行模型会话。

## 已实现

1. 产品入口改用 quota-free request ledger。连接信息只给请求记录统计，不给剩余额度；UI 移除试用倒计数、耗尽提示与发送限制。保留旧有受限 helper 仅供历史实验测试，产品不会引用它。
2. 首次新增调用在文件锁内将旧 v1 账本迁移为 v2，原样保存六条历史记录和备份。备份写出后中断可再次迁移；备份不一致、损坏账本或未确认的 reserved 请求保持可见错误，不能通过清空记录解除。
3. 普通回应从本地提交开始显示“正在思考”；失败为“这次回复未完成”。新输入尚未确认时，停止按钮不能取消上一条选中对话。
4. 适配器允许 `displayable_summary` 可选字段（非空字符串，最多 800 字符）。它被移出 ModelDecision，经既有 `displayableSummary → provider_summary` 通道保存。模型私有 `reasoning_content` 不转发。摘要缺失时不构造假思路，摘要不会成为执行证据。
5. 工具卡只由可信活动投影器产生；CSV 的真实事件、完成状态和来源可展开查看。历史完整记录可继续显示工具结果，不因切换到别的对话而消失。

## 边界

- 当前回复及摘要在完整模型输出通过检查后出现，还不是逐 token 流式输出。
- 新摘要不会给旧对话补造推理记录。历史列表预览须打开完整内容后才能获得该条完整摘要/工具详情。
- 模型内容仍为不可信文本；工具、权限、记忆和联系计划由既有 Python 内核校验。旧冻结内核不变。
- 取消本地额度不改变供应商本身的余额、限流或超时行为；这些已有错误继续准确显示。
- 后台主动联系、自由 UI 代码执行、原生隔离、官方 Coding Agent、TTS、社区分享都未在本批开放。

## 下一阶段开发顺序

### 1. 连续对话与可见执行

建立统一、带 turn/run/event ID 的流式事件通道。公开思路摘要、回复增量、工具开始/结果分别处理。部分模型 JSON 永不执行；最终校验通过后才交给内核。停止、切换、重连、进程重启不会重复模型请求或工具副作用。验收包括真实串行多轮、网络中断、取消竞争、重开历史和实际工具结果来源。

### 2. 自由改版闭环

用户一句话提出外观/交互诉求 → Coding Agent 或模型写代码 → 独立隔离预览 → 用户启用 → 保留上一版本随时回退。复用原代码包、静态审查与窄桥基础，不改成模板选择器。身份、记忆、任务和授权留在可信宿主。验收以“换整个界面后继续同一段对话并回退”为完整演示，原生隔离没有证据前不得宣称可执行任意代码。

### 3. 主动参与生活

默认关闭、用户开启后，由模型决定联系内容和时机；普通聊天不预告发送时间。后台生命周期、安静时段、免打扰、去重、过期复核和送达后解释组成闭环。先应用内真实送达，再考虑桌面通知和 TTS。复用已有主动联系协调器与共享执行槽。

### 4. 可携带的个性化

导出/导入界面代码包、技能及明确选择的人格设置；私人记忆、会话和凭据默认不进入分享包。先完成本地可检查包，再开发社区展示和 Fork。
