# CORE-015 · 模型主导的目标模式与 Claude Code

本批在 CORE-014 的持久步骤和单执行槽上扩展，不新造通用 Agent 框架。用户要求模型负责拆分、分派、验收和返工；程序负责提供可用工具与真实状态。使用 DeepSeek，串行调用；不运行 Codex，不使用当前 OpenAI 账号，不创建额外 Codex 会话。

## 模块与边界

1. Python goals 扩展：目标、任务、依赖、执行轮次、提交证据和逐项验收在现有数据库事务中保存。主控可增加任务、选择就绪任务和执行器；工作者只能处理当前任务。执行者提交后必须切回主控验收，不能自写 accepted。验收引用本轮真实成果，可辅以已验收依赖任务的成果；不接受无关任务/旧轮次的证据。退回意见供下一轮工作者读取。取消与陈旧票据沿用原链。
2. Provider 路由：主控、工作者、验收分别配置模型；允许三者相同，不把角色隔离说成模型质量提升。主控接收目标/任务状态，工作者只接收当前任务和相关材料/依赖证据；工具动作仍由现有执行器执行。目标不因一个子任务结束而提前终止。
3. Claude Code：复用本机官方 CLI，以 bare 非交互模式运行，独立配置目录与新工作目录，通过 DeepSeek Anthropic 兼容接口。只给明确目录内的文件读取/修改工具；无通用 Shell、外部连接器或隐式子智能体。宿主收集实际文件、进行代码语法检查，绑定哈希与过程回执供主控验收。源码不会自动安装或运行任意程序。
4. 默认界面与 SDK：轻量目标模式入口、主控/执行/验收身份、任务依赖与返工状态，复用任务卡、停止和继续。更换前端仍共享同一目标状态。界面不伪造思维链、百分比或验收。
5. 真实验证与交付：先离线验证拒绝、返工、依赖、错误归属、停止/恢复与互斥，再串行运行一个真实 DeepSeek 多角色目标及一个真实 Claude Code 编码任务。保留实际工具和文件证据；CLI 请求数和外部 API 请求数分别记录，不混淆一次 CLI 启动与一次模型请求。

## 验收与限制

- 模型自由决定任务内容和验收标准；状态约束防止跳过主控验收、依赖未完成先执行、跨任务伪用成果和无权限执行。
- 正常聊天不启动多角色。显式目标模式才开启；普通 CORE-014 回归不得变化。
- 一轮通常一个调度动作；允许主控把 plan→dispatch 放在同一轮，规划失败则派工不执行。工具步骤允许空说明文字和空结束标志，最终答复仍必须有非空文本和明确结果。其余跨角色组合继续拒绝。
- 每项目标最多 12 个任务、每任务最多 4 次派工；每连续 24 次判断保存检查点，最多 192 步。不是账户费用预算；暂停后用户可继续，异常网络不自动重试。
- Claude 文件工具的权限边界是 CLI 授权规则，不宣称为操作系统级敌对代码沙箱。宿主语法检查不等于程序行为测试；任意宿主源码执行、部署和安装仍不默认开放。
- 本阶段以本地运行的持久目标为范围；关机后云端继续、多机协作、整套 UI 自然语言作者仍后置。

协议来源：本机 Claude Code 2.1.215 `--help`；[Claude 非交互接口](https://code.claude.com/docs/en/headless)；[DeepSeek Anthropic 接口](https://api-docs.deepseek.com/guides/anthropic_api/)。实际连通、请求数量和检查范围见 `reports/core-015/report.json`。
