# 架构师下一轮核心开发计划

计划对象：Companion Agent / Personal AI。当前依据为 ADR-002、ADR-003、ADR-005/006/007，以及 BATCH-016-R1 复核与 BATCH-016-R2 派工。此文件是开发建议，尚不代表已经执行，也不修改正在开发的 R2 写集或基线。

2026-09-24产品补充：交互细节以同目录 `personal-ai-product-experience-v1.md` 为依据。长期记忆默认开启且可定制/关闭；主动联系默认关闭，允许用户轻量开启后由模型自主安排有时效的跟进。这两项纳入首版核心，不推迟到社区、语音或云服务之后。此补充只更新独立计划，不向当前批次追加写集。

## 本轮目标

把已实现的个人身份、任务服务、进程桥和界面代码包连接成一个有明确调用入口的产品核心。前端以后通过少量稳定接口接入，同一个个人AI可以保留交互记录、提出行动、执行已授权工具，并切换界面而不中断身份和任务。

第一轮以可运行的本地单用户纵向链路为范围。不将离线模型回执测试宣称为自然语言理解或真实Agent验收。初始视觉单独由架构师设计，开始前通知用户调整推理档位。

## 0. 并行开发边界与复用清单

- R2执行者继续拥有host/client桥和对应修订测试；本计划在独立本地开发副本开展，避免任何新文件被原工作区的冻结范围检查计为越界。不开额外模型会话或子智能体。
- 开始实现前核对并复用现有personal_ai、local_tasks、desktop_bridge、personal-space/core/authoring/host；对每块明确哪些可直接导入、哪些还只是实验。保留依赖锁和已有验证器，不重写通用Agent、任务调度器或前端模板引擎。
- 每个进程启动前断言实际模块导入根，测试只使用新建的数据根。禁止复用旧015/016/R1/R2运行数据库；旧源文件、报告和基线保持原样。
- 新模块经窄端口连接旧模块；R2独立复核通过后再进行最终桥接集成。架构接口或旧服务必须修改时，在本轮明确记录兼容影响和迁移办法。

## 1. 交互与任务的产品核心（最高优先级）

目标：为未来极简入口提供统一的交互生命周期，避免前端分别拼装聊天、偏好、任务和代码包实验。

输入：稳定个人AI身份、用户输入、用户明确选择的材料引用、当前偏好修订、一次交互的标识。

输出：持久交互记录、模型建议或澄清、待执行动作、真实任务引用、可订阅状态和最终结果引用。

开发顺序：
1. 冻结有限的交互状态和应用接口；以现有Pydantic为权威，不手写第二套业务Schema。
2. 增加交互/消息及动作关联的本地持久化。这是产品运行记录，不另建语义记忆系统或向量库。
3. 用可替换的模型/Agent端口接收文本和结构化行动建议。模型返回建议不能直接修改任务状态；执行完成由工具回执决定。
4. 支持明确的输入不足、调用失败、用户取消、进程重开和未知结果读回。保留必要上下文，不保存或依赖模型隐藏思维链。

验收：同一用户输入不会因重复提交创建多个实际任务；关闭重开可恢复交互与任务关系；模型口头宣称完成但无真实结果时，产品仍显示实际状态；损坏模型回执无业务副作用。

## 2. 统一的动作与能力入口

目标：用户对话、可信前端和可替换界面调用同一套受控应用能力，权限不随模型文本或换肤改变。

输入：调用实例、明确动作、参数、现有授权上下文及关联标识。

输出：允许/拒绝/确需用户补充授权，以及已验证的真实执行回执。

开发顺序：
1. 先登记少量现有能力：读取/修改显式偏好、提交/查询/取消本地CSV任务、读取界面版本与提出候选。复用原服务幂等和CAS，不另建竞争任务表。
2. 绑定调用来源、个人AI和动作作用域；调用者自报身份或权限不能构成授权。
3. 明确取消、权限撤销和结果未知的行为；重复请求复用原command_id，不把超时当作未执行。
4. 输出给模型和前端的事件由同一真实回执产生。暂停/停止/恢复入口不依赖模型在线。

验收：同一动作从不同入口得到一致的业务结果；未授权参数被拒绝；撤销后排队新动作不再执行；正在退出的进程和已取消任务不会混为一谈。

## 3. 个性化代码包与稳定状态的集成

目标：把现有可编辑HTML/CSS/JS包、封存、校验和回退能力接到同一个Personal AI上，为“让AI替换自己的界面”做好真实产品接口。

输入：当前界面版本、候选源码、验证结果、明确启用意图。

输出：候选修订、验证反馈、已激活版本或保持旧版的失败结果、可恢复版本。

开发顺序：
1. 复用现有authoring/core版本与校验逻辑，补齐产品层引用关系，不重写构建器。
2. 建立个人AI→当前体验版本→源码/产物hash的稳定绑定；任务和交互数据留在应用服务。
3. 发布按base revision进行比较，过期候选不能覆盖新选择；失败保留上一可用版本。
4. 将就绪、替换、卸载、恢复通过可信宿主端口连接起来。原生隔离未通过前只使用可信手写fixture；模型代码继续仅做静态候选处理。

验收：任务运行时切换可信界面版本，个人身份、偏好、任务id及结果不丢失；坏包不替换好包；回退界面不会回退任务或复活已撤销权限。它不提供官方多模板选择器，也不宣称模型代码已经可以安全运行。

## 4. 可管理的记忆与主动联系

目标：形成用户能理解、修改和停止的个性化与主动关心闭环。界面只负责呈现同一份服务状态，改版不能改变开关含义。

输入：稳定身份、明确设置、经授权可用的互动来源、记忆规则、主动联系规则与时区、当前设备运行能力。

输出：带来源的可管理记忆、内部跟进计划、到期复核结果、持久消息及投递状态。依用户最新修订，普通对话与首页不预告自动消息或时机；保留设置控制、短期信息管理和事后联系原因，用户明确交办的提醒仍正常确认。

开发顺序：
1. 核对已有记忆端口与调度能力，复用可用实现；先定义来源、删除/停用及数据保留边界，不额外搭建竞争的向量记忆或运行调度器。名字等明确设置保持原有权威存储。
2. 接入记忆读取、添加、编辑、忘记、范围限制与总开关。关闭使排队中的读取/提取/写入失效；删除后不能由同一来源自动重新学回。界面能解释原聊天和长期记忆的区别。
3. 持久化主动联系授权和FollowUpPlan：来源、目的、时间窗口、时区、有效期、必要短期上下文、取消条件和规则版本。默认关，不逐条重复批准授权内的普通问候。
4. 模型端口可以提出计划；运行服务校验主题、时段、频率与预算后保存。到期重新判断是否仍有价值，再经过发送前规则检查，形成同一持久收件箱中的消息；不可仅靠进程内计时器维持计划。
5. 关闭/暂停/取消话题可阻止待生成与待投递项目；用户明确的单次提醒或重复任务独立授权。长期记忆关闭时，不以短期笔记为名复制旧记忆绕过关闭。
6. 建立应用内收件箱、去重及真实送达状态；本地休眠/退出后按时效恢复，过期问候不集中补发。系统通知和云端运行分阶段接入，不先承诺设备离线仍能工作。

验收：默认状态正确；开启后合成模型能提出一条真实持久计划；进程重开计划不丢；到期复核可取消不合时宜的跟进；未回复不自动追问；关闭与投递竞态不绕过新规则；记忆关闭/删除传播到后续检索和依赖计划。使用可控时钟完成离线验收，不额外向用户真实发送消息。

语义提取、关心时机和表达质量须单列真实模型验收；离线回执只证明产品链路。当前预算下不发模型请求。

## 5. 纵向集成与交付

五个必要场景：
1. 用户明确修改称呼/语气→模型端口给出建议→应用服务应用→重开仍保留同一身份与偏好。
2. 用户交付CSV材料→受控动作→真实本地worker→可追踪结果；覆盖取消、断开、重复请求和显式恢复。
3. 可信界面候选→校验→切换/回退，同时验证正在运行的任务及交互记录连续。
4. 用户管理一条带来源的记忆→修改/关闭/忘记→后续检索和排队提取确实受新规则限制，明确设置保持独立。
5. 主动联系默认关→用户开启→模型端口提出跟进→真实保存→进程重开→可控时间到期复核→应用内消息；另外验证情况已解决时取消、用户关闭时取消以及不回复不追问。

离线使用合成模型输出验证动作与状态边界，真实CSV处理必须经过实际Node/Python/SQLite链路。真实模型语义质量另列验收，不能用合成输出冒充已完成。

交付内容：可运行代码、必要契约、能重复执行的五个演示、关键故障回归、前端接线说明和完成/未完成清单。以真实行为而不是文档数量或通过测试数量衡量进度。

## 暂不进入本轮

正式视觉、TTS、社区、手机端、多租户云部署、持续屏幕观察、自动外部发送/消费以及新一轮模型试验。当前DeepSeek历史两次请求额度已经用完，保留适配端口；补充真实请求需单独明确范围，不使用当前OpenAI账号发起附加请求。

## 里程碑顺序

M1：交互核心与统一动作入口能驱动真实本地任务。

M2：个性化版本接入同一身份和稳定状态，可信fixture替换/恢复通过。

M3：可管理记忆、主动联系规则、跟进计划与应用内收件箱形成离线可核验闭环；语义质量仍单列。

M4：R2桥修订独立通过后，完成组合运行与故障验收，准备让架构师设计的简洁UI接线。正式视觉设计开始前通知用户。

若窗口不足，优先交付M1的完整闭环，不同时铺开全部模块留下空壳；各里程碑留下精简检查点，后续可接续。
