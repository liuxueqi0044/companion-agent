# CORE-014：同一任务的执行、观察和修正

目标：用户附上 CSV 并说清需求后，AI 可以在一个持续任务中检查材料、编写查询、读取真实结果、修正失败、保存成果或可复用工具，最后依据回执回应。普通聊天仍是一次回应。整套 UI 的自然语言作者继续后置。

## 结构与顺序

1. **持久步骤**：在 product.sqlite3 加入两个可验证的附加表，保留已有表和存储版本。步骤、模型票据、计划摘要、动作 ID 由内核事务绑定。原始推理链不保存、不伪造。
2. **真实执行与观察**：复用 CORE-013 的只读 SQLite 引擎，新增一次性 `data.query`，无需为了临时分析保存一个工具。仅接收本次显式附件；输出限额、SQL authorizer、成本限制沿用原实现。结果为可下载 JSON。后续模型上下文收到真实回执、有限结果样本和截断说明，不能把生成的报告当成计算证据。
3. **串行协调**：宿主独立授予 `task.loop`；每一步重新获取票据、校验政策/材料/工具目录。一个执行槽覆盖整个循环和子进程清理。执行结果不明时停止，不自动重放。已确认步骤不会在恢复时重复执行。
4. **防止空转与恢复**：连续八次模型判断后暂停，用户可继续；整项任务最多 64 次判断，之后需新任务。这里是单项循环的资源边界，不是账户调用预算。网络失败不重试。重复写入同一个动作被拒绝；工具失败可由下一次判断修正。停止撤销权限；停止后的旧结果不能继续。服务重启不会自动恢复模型请求，由用户继续。
5. **默认 UI 和共享 SDK**：在现有大任务卡展示公开计划、每步摘要和真实动作状态；继续、停止、成果下载复用共享能力。换用自定义前端仍读取同一状态。最终回答与历史中间步骤分开，失败步骤不会被抹掉。

## 验收

- 离线真实 Node → Python → SQLite：查询失败 → 模型读取失败 → 修正查询 → 读取结果 → 保存报告 → 最终说明；也验证工具创建后在同一任务内使用。
- 无权限、陈旧票据、目录/政策变化、重复动作、超限暂停、恢复、停止、晚到结果、写入状态不明及同槽互斥。
- 旧聊天/工具/提醒/前端包回归；Schema、SDK 类型、旧工作区只读完整性。
- 一次真实串行 DeepSeek 多步任务，用虚构 CSV；记录实际请求数和动作回执，不声称模型语义普遍可靠。
- 最后更新本地服务、当前文档和代码发布镜像；历史报告不改。

## 边界

本批完成通用协调循环的第一个受控执行器实例。没有任意 shell、Python/Node 生成代码、网页/电脑操作、外部发送；也不是已经接通所有 Coding Agent。官方 Codex/DeepSeek 协议兼容性和独立执行沙箱留作后续接入，不能以未经验证的配置冒充完成。计算的业务正确性仍需用户核对；SQL 数值继续遵循 SQLite 普通数值语义。
